# CI Phase 1.1 — Aggregator Gate + Docs Path-Skip — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make branch protection require a single *computed* gate (`ci-required`) instead of 5 individual job checks, so conditional execution is safe — then skip the heavy suite on docs-only PRs (fast docs). Closes the Phase 1 skip-success class permanently.

**Architecture:** A cheap `changes` job detects whether any non-doc file changed; the heavy jobs gate on `changes.code == true` (and not-draft); an always-running `ci-required` aggregator computes pass/fail explicitly from `needs.*.result` + `changes.outputs.code`. Branch protection then requires only `ci-required`. Because the verdict is computed (not GitHub's "skipped required = passing" default), a skipped job can never silently pass. Design approved via brainstorming 2026-06-24; revised after Codex review (2 P1 fixes) + user decisions. Builds on Phase 1 ([2026-06-24-ci-trigger-redesign-plan.md](2026-06-24-ci-trigger-redesign-plan.md)).

**Tech Stack:** GitHub Actions YAML, `gh` CLI / GitHub REST (branch protection — admin), `rg` + `python -c "import yaml"` for verification.

## Approved Design (reference)

**Job graph (new `pr.yml`):**

```
changes        cheap; skips on draft. Diffs base…head → outputs code=true|false
policy         skips on draft — unchanged from Phase 1
brand-check    skips on draft — unchanged from Phase 1
verify         needs: changes; runs iff code==true AND not-draft
e2e            needs: changes; runs iff code==true AND not-draft
migrations     needs: changes; runs iff code==true AND not-draft
verify-cross-platform / e2e-cross-platform   same gate; stay advisory (continue-on-error)
ci-required    needs all 6; runs ALWAYS (if: !cancelled()); computes the verdict
```

**`not-draft`** = `(github.event_name != 'pull_request' || !github.event.pull_request.draft)`.

**`ci-required` verdict (the keystone, Codex-corrected):**
- `changes` must be `success` (on a draft it's skipped → gate goes **red**: drafts are unmergeable and must not produce a passing required check).
- `policy` and `brand-check` must be `success`.
- **Only when `code == true`**: `verify`/`e2e`/`migrations` must be `success`. When `code == false` (docs-only) they're skipped and that's allowed.

So: docs-only PR → heavy skipped → gate green fast; code PR → heavy must pass; draft → gate red (zero CI burned, fail-closed); a heavy job skipped on a *code* PR → gate red. No skip-success path on any mergeable PR.

**Docs skip-set:** docs-only (`code=false`) iff **every** changed file is under `docs/` OR is a **root-level** `*.md` (README/CLAUDE/AGENTS). Any `.github/**` file, any **nested** `*.md` (runtime prompt assets under `server/src/onboarding-assets/**`, fixtures, package READMEs), or any other path ⇒ `code=true` ⇒ full CI. The detector uses `git diff --no-renames` so a code file moved into `docs/`/`*.md` still classifies its deleted source as code. Conservative — errs toward running CI. (Tightened from the first draft after Codex PR review; see below.)

**Draft behavior (user decision):** drafts keep zero-CI gating (all real jobs skip); `ci-required` shows **red** on drafts ("not validated yet"). Marking ready runs the real suite → green.

**Governance — deferred (user decision):** it's a solo repo (1 collaborator); required reviews would block your own PRs (no second approver), and the aggregator already closes the skip-success bypass that reviews would backstop. So **no CODEOWNERS and no required reviews in 1.1.** Add the whole governance layer (CODEOWNERS + required reviews + code-owner enforcement) the day a second committer with write access joins.

**Out of scope → Phase 1.2:** GitHub Merge Queue (retarget/staleness). `strict` branch protection stays **off** (user decision — merge queue handles staleness without the rebase friction). Retarget stays "push to re-trigger." Do NOT re-add `edited` (Phase 1 P1).

## Task 1: Add the `changes` detection job

**Files:**
- Modify: `.github/workflows/pr.yml` (add a new job at the top of `jobs:`, before `policy`)

- [ ] **Step 1: Add the `changes` job**

Insert this as the first job under `jobs:` (immediately after the `jobs:` line, before `policy:`):

```yaml
  # Cheap change-detector: decides whether the heavy suite needs to run.
  # docs-only (code=false) iff EVERY changed file is under docs/ or is a *.md
  # OUTSIDE .github/. Any .github/** file, or any other path, => code=true =>
  # full CI. On push (main) code is always true. Skips on draft (zero CI).
  changes:
    runs-on: ubuntu-latest
    if: ${{ github.event_name != 'pull_request' || !github.event.pull_request.draft }}
    timeout-minutes: 5
    outputs:
      code: ${{ steps.detect.outputs.code }}
    steps:
      - name: Checkout repository
        uses: actions/checkout@34e114876b0b11c390a56381ad16ebd13914f8d5 # v4.3.1
        with:
          fetch-depth: 0
      - name: Detect non-doc changes
        id: detect
        run: |
          if [ "${{ github.event_name }}" != "pull_request" ]; then
            echo "code=true" >> "$GITHUB_OUTPUT"
            echo "push event -> code=true"
            exit 0
          fi
          changed="$(git diff --no-renames --name-only "${{ github.event.pull_request.base.sha }}...${{ github.event.pull_request.head.sha }}")"
          if [ -z "$changed" ]; then
            echo "code=true" >> "$GITHUB_OUTPUT"
            echo "empty diff -> code=true (fail safe)"
            exit 0
          fi
          code=false
          if printf '%s\n' "$changed" | grep -qE '^\.github/'; then
            code=true        # any .github/** file (incl .github/*.md) => full CI
          elif printf '%s\n' "$changed" | grep -qEv '^docs/|^[^/]+\.md$'; then
            code=true        # anything not under docs/ and not a ROOT-LEVEL *.md
                             # (nested .md may be runtime assets/fixtures => code)
          fi
          echo "code=$code" >> "$GITHUB_OUTPUT"
          echo "changed files:"; printf '%s\n' "$changed"
          echo "=> code=$code"
```

## Task 3: Add the `ci-required` aggregator

**Files:**
- Modify: `.github/workflows/pr.yml` (add a final job after all others)

- [ ] **Step 1: Add the aggregator job**

Append as the LAST job under `jobs:`:

```yaml
  # Single required status check. Branch protection requires ONLY this job.
  # Runs ALWAYS (`!cancelled()`), even when upstream jobs fail or skip, and
  # computes the verdict explicitly so a `skipped` job cannot silently pass —
  # closing the Phase 1 skip-success class. On a draft PR `changes` is skipped,
  # so this gate goes RED (drafts are unmergeable; a passing required check
  # there would be the footgun). Marking ready re-runs everything for real.
  ci-required:
    needs: [changes, policy, brand-check, verify, e2e, migrations]
    if: ${{ !cancelled() }}
    runs-on: ubuntu-latest
    timeout-minutes: 2
    steps:
      - name: Evaluate required gate
        env:
          R_CODE: ${{ needs.changes.outputs.code }}
          R_CHANGES: ${{ needs.changes.result }}
          R_POLICY: ${{ needs.policy.result }}
          R_BRAND: ${{ needs['brand-check'].result }}
          R_VERIFY: ${{ needs.verify.result }}
          R_E2E: ${{ needs.e2e.result }}
          R_MIGRATIONS: ${{ needs.migrations.result }}
        run: |
          echo "code=$R_CODE | changes=$R_CHANGES policy=$R_POLICY brand-check=$R_BRAND verify=$R_VERIFY e2e=$R_E2E migrations=$R_MIGRATIONS"
          fail=0
          # Detector must have succeeded. Skipped (draft) => red, by design.
          if [ "$R_CHANGES" != "success" ]; then
            echo "::error::changes detector not success ($R_CHANGES) — draft or detector failure"
            fail=1
          fi
          # Always-on cheap gates must pass.
          for kv in "policy=$R_POLICY" "brand-check=$R_BRAND"; do
            name="${kv%%=*}"; res="${kv#*=}"
            [ "$res" = "success" ] || { echo "::error::$name=$res (required)"; fail=1; }
          done
          # Fail closed on an unexpected detector output (defense in depth):
          # if changes succeeded, code MUST be exactly true or false.
          if [ "$R_CHANGES" = "success" ] && [ "$R_CODE" != "true" ] && [ "$R_CODE" != "false" ]; then
            echo "::error::invalid changes.outputs.code ($R_CODE)"
            fail=1
          fi
          # Heavy jobs required to pass ONLY when code changed. On a docs-only
          # PR (code=false) they are skipped, which is allowed.
          if [ "$R_CODE" = "true" ]; then
            for kv in "verify=$R_VERIFY" "e2e=$R_E2E" "migrations=$R_MIGRATIONS"; do
              name="${kv%%=*}"; res="${kv#*=}"
              [ "$res" = "success" ] || { echo "::error::$name=$res (required for code changes)"; fail=1; }
            done
          fi
          [ "$fail" = "0" ] && echo "ci-required: PASS"
          exit $fail
```

## Codex review (2026-06-24)

Independent review of this plan via `/codex review` (read-only). Found 2 real P1s — both fixed above:

- **[P1] Aggregator allowed skipped heavy jobs on code PRs.** Original logic allowed `skipped` unconditionally; a skipped `verify`/`e2e`/`migrations` on a *code* PR would have passed. **Fixed:** aggregator reads `R_CODE = needs.changes.outputs.code` and requires heavy jobs `== success` when `code == true` (Task 3).
- **[P1] Draft skip-success residue.** Original skipped `ci-required` on drafts → skipped-success required check → bypass window after `ready_for_review`. **Fixed:** `ci-required` runs always (`if: !cancelled()`) and goes red on drafts (Task 3); confirmed by user (keep draft-gating, red on drafts).
- **P2s fixed:** docs detector reclassifies `.github/*.md` as code (Task 1); failing-test smoke uses a real TS2322 error (Task 7); migration verifies both `.checks` and `.contexts` (Task 6).
- **Constraint surfaced + decided:** solo repo (1 collaborator) ⇒ required reviews would block your own PRs and aren't needed once the aggregator closes the bypass. Governance (CODEOWNERS + reviews) **deferred** to when a second committer joins (user decision). `strict` stays false; merge queue → Phase 1.2 (user decisions).
- **Re-review (revised plan): SAFE TO IMPLEMENT.** Codex confirmed both P1s fixed, no new P1. One P2 hardening incorporated (Task 3): fail closed if `changes.outputs.code` is neither `true` nor `false` when the detector succeeded.
- **PR-time cloud review (on #231) — 2 detector issues fixed:** **[P1]** `git diff --name-only` reports only a rename's destination, so moving a code file into `docs/`/`*.md` would skip CI on the removed source → fixed with `--no-renames` (Task 1). **[P2]** runtime prompt assets (`server/src/onboarding-assets/**/*.md`, loaded by `loadDefaultAgentInstructionsBundle`, with behavior tests) were classified docs-only by the blanket `*.md` rule → fixed by tightening to **root-level** `*.md` (nested `*.md` ⇒ code), Task 1. Both make the detector strictly more conservative.
