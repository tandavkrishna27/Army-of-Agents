## Task 1: Fix A — bridge fatal handlers exit loudly (codex P2)

**Files:**
- Modify: `server/src/services/internal-agent/mcp-bridge.ts:169-176` (the two `process.on` handlers inside `startBridge`)

**Context for the implementer:** The codex bot flagged (P2) that these handlers log to stderr and `return`, suppressing Node's default crash so a genuinely-broken bridge can keep running wedged. A process-level fatal error must kill the bridge (exit 1) so the parent CLI sees it die and the loud-failure detector marks the run failed. This is distinct from the watchdog-only stdin-EOF lifecycle (which terminates via the parent-liveness watchdog with exit **0** — leave that untouched). Malformed/partial frames route to `transport.onerror` (logged), NOT to these handlers, so the existing Task-8 malformed-frame edge test (asserts no `MCP Bridge fatal (uncaughtException|unhandledRejection)` markers) stays green — the handlers only fire on genuine uncaught errors the tests don't trigger.

**No new unit test:** deterministically inducing a real `uncaughtException`/`unhandledRejection` in the well-isolated bridge (without restructuring `startBridge`) is impractical, and asserting on `process.exit` in-process is not clean. This is a defensive change verified by NO-REGRESSION (Task 3 runs the integration + watchdog + unit suites against a live DB — that is the real check that exit-on-fatal didn't break normal bridge operation). Do NOT add a contrived test.

- [ ] **Step 1: Apply the change.** Replace the two handlers (lines 169-176) with:
```ts
  process.on("unhandledRejection", (reason) => {
    process.stderr.write(`MCP Bridge fatal unhandledRejection: ${String((reason as any)?.stack ?? reason)}\n`);
    // A process-level rejection is genuinely unexpected (per-tool errors are
    // isolated in executeAndFormat). Fail LOUD: exit so the parent CLI sees the
    // bridge die and the loud-failure detector marks the run failed, rather than
    // limping on in an undefined state. Distinct from the watchdog (exit 0).
    process.exit(1);
  });
  process.on("uncaughtException", (err) => {
    process.stderr.write(`MCP Bridge fatal uncaughtException: ${(err as any)?.stack ?? err}\n`);
    process.exit(1);
  });
```
Leave the surrounding `// ── Global fatal handlers (loud, not silent) ──` comment block header in place; the per-handler comment above explains the exit. Do not touch anything else in `startBridge`.
