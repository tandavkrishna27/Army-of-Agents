# Memory Page Redesign — Phase 6.2f (Folder-First Central Pane) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rewrite the memory explorer's central pane to behave like Windows Explorer — when you click a folder, you see **subfolders + items at this level**, not aggregated descendants. Drop the category grouping. Folders on top, items below. As a polish add-on, exclude archived items from the tree's layer/dept counts so the totals match what's visible by default.

**Architecture:** UI-only refactor of `MemoryFileList`. The component grows a `memory_folders` query (already loaded by `MemoryTree`, just re-uses the same cache) to know its subfolder children. Two sections render: **Folders** (clickable tiles that navigate into them) and **Items at this level** (filtered to `folderPath === currentPath` exactly). Layer-only / virtual-folder modes keep their existing aggregating behavior — the strict-path semantics only apply when you've navigated to a real folder/scope.

**Tech Stack:** React + Vite + TailwindCSS, `@tanstack/react-query`, vitest + RTL.

**Spec source:** Brainstorm decisions on 2026-05-04 — Option A (strict path semantics).

**Branch + worktree:** `memory-6.2f-folder-first` in `.claude/worktrees/memory-6.2f-folder-first/`. Most recent commit on `memory`: `451dfbc`.

**Out of scope (later):**
- Category filter pill bar (would replace the grouping if founder wants to slice by category).
- Drag-and-drop folder rearrange.
- Memory access model (Phase 6.2d, deferred).

## Behavior matrix — what shows in the central pane per scope

| Tree selection | URL params | Folders section | Items section |
|---|---|---|---|
| 🏠 Home | (no params) | Home dashboard (unchanged) | (Home dashboard) |
| 📌 Pinned | `folder=__pinned` | (none) | All items where `founderPinnedToTop=true`, ungrouped |
| 📋 Pending | `folder=__pending` | (none) | All items where `status='pending'` |
| 🕒 Recent | `folder=__recent` | (none) | Last 14 days |
| 📦 Archived | `folder=__archived` | (none) | All items where `status='archived'` |
| 🪪 Identity (layer hdr) | `layer=identity` | (none — Company shows under Identity in tree) | All identity items, ungrouped |
| 🏢 Domain (layer hdr) | `layer=domain` | (none — depts show under Domain in tree) | All domain items, ungrouped |
| 🎯 Active Context (layer hdr) | `layer=active_context` | Active goals as folder tiles | (none — items live under goals) |
| ⚡ Working (layer hdr) | `layer=working` | (none) | All working items, ungrouped |
| 🏛️ Company (Identity scope) | `folder=Company&dept=null` | Direct subfolders of Company (1-level) | Items where `folderPath='Company'` exactly |
| 📁 Engineering (dept) | `dept=d-eng` | Direct subfolders of `engineering/` (Decisions, Policies, References, Files, Q3 Planning, …) | Items where `folderPath='engineering'` exactly |
| 📂 Engineering/Decisions (seeded folder) | `folder=engineering/Decisions&dept=d-eng` | Direct subfolders of that path (rare for seeded) | Items where `folderPath='engineering/Decisions'` |
| 📂 Engineering/Q3 Planning (user folder) | `folder=engineering/Q3+Planning&dept=d-eng` | Sub-user-folders | Items where `folderPath='engineering/Q3 Planning'` |

**Key change:** the dept node now shows ITS subfolders + items at the dept root. Today it aggregates everything across the dept. Items in `engineering/Decisions` no longer appear when you click Engineering — you click into Decisions to see them.

**Aggregating modes (unchanged):** Pinned / Pending / Recent / Archived / Identity-layer / Domain-layer / Working-layer keep aggregating because they're filters, not folder paths.

**Hybrid mode for Active Context layer:** clicking the layer header shows GOALS as folder tiles (since goals are sub-scopes the user can drill into). No items at "active_context root" — that's a dead space.

- [ ] **Step 4: Compute the subfolders to render.**

Add this memo after the existing `rows` memo. The logic differs based on what scope is selected:

```typescript
const subfolders = useMemo<MemoryFolderRecord[]>(() => {
  // Virtual / layer-only / aggregating modes show no subfolder section.
  if (isVirtualFolder || isLayerOnly || !folderPath) return [];
  // For folder paths (dept slug or seeded/user folder), show direct children only.
  // Direct child: path startsWith currentPath + "/" AND remainder has no "/".
  return (folders ?? [])
    .filter((f) => {
      if (!f.path.startsWith(folderPath + "/")) return false;
      const remainder = f.path.slice(folderPath.length + 1);
      return remainder.length > 0 && !remainder.includes("/");
    })
    .sort((a, b) => {
      // Seeded folders first by sortOrder, then user folders alphabetically.
      const aSeed = a.seedKey !== null;
      const bSeed = b.seedKey !== null;
      if (aSeed !== bSeed) return aSeed ? -1 : 1;
      if (aSeed) return a.sortOrder - b.sortOrder;
      return a.displayName.localeCompare(b.displayName);
    });
}, [folders, folderPath, isVirtualFolder, isLayerOnly]);
```

Add a per-folder item-count helper so each folder tile can show "(N items inside)":

```typescript
const folderItemCounts = useMemo(() => {
  const map = new Map<string, number>();
  for (const it of (itemsQuery.data ?? []) as Array<MemoryItem & { folderPath?: string; status?: string }>) {
    if (it.status === "archived") continue;
    const p = it.folderPath ?? "";
    map.set(p, (map.get(p) ?? 0) + 1);
  }
  // For each subfolder, sum its descendants too.
  return (path: string) => {
    let total = 0;
    for (const [itemPath, count] of map.entries()) {
      if (itemPath === path || itemPath.startsWith(path + "/")) {
        total += count;
      }
    }
    return total;
  };
}, [itemsQuery.data]);
```

(This is a closure-style helper — call `folderItemCounts(f.path)` per folder to get its rolled-up count.)
