# M.4 Plugin Management Design

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make plugins fully company-scoped, implement the upgrade flow end-to-end, and replace the Company Settings → Plugins tab with a rich management UI that covers install visibility, configuration, and upgrades — all in one place.

**Architecture:** Plugins move from instance-scoped (no `companyId`) to company-scoped (`companyId NOT NULL`). The plugin-loader threads `companyId` through all install/load/upgrade paths. The Company Settings → Plugins tab becomes the single authoritative destination for plugin management. The Instance Settings → Plugins tab is simplified to diagnostics only.

**Tech Stack:** Drizzle ORM (schema migration), Express 5.x (routes), React + Vite + TailwindCSS (UI), existing `plugin-loader.ts` / `plugin-lifecycle.ts` / `plugin-worker-manager.ts` / `marketplace-update-checker.ts`.

| Schema | `packages/db/src/schema/plugin_config.ts` | No `companyId` — instance-wide |

| Service | `server/src/services/plugin-lifecycle.ts` | State machine on `pluginId` UUID — no company awareness |
| Service | `server/src/services/marketplace-install/plugin-installer.ts` | Calls `pluginLoader.installPlugin()` — version mismatch throws "Upgrade flow lands in M.4" |
| Service | `server/src/services/marketplace-update-checker.ts` | Scans skills only — does not scan `plugins` table |
| Route | `server/src/routes/plugins.ts` | `POST /api/plugins/:pluginId/upgrade` — skeleton with rollback but `lifecycle.upgrade()` body not implemented |
| UI | `ui/src/pages/SettingsPage.tsx` (PluginsSection) | Simple toggle list only — no config form, no upgrade UI |
| UI | `ui/src/pages/InstanceSettingsPage.tsx` | Full install/config/health UI — to be simplified |

### What M.4 delivers

1. **Schema migration** — `companyId` on `plugins` + `plugin_config`, updated unique constraints, data backfill
2. **Plugin loader refactor** — `companyId` threaded through all install/load/upgrade paths; registry keyed by `(companyId, pluginKey)`
3. **Upgrade flow** — implement `lifecycle.upgrade()` body; capability delta comparison; `upgrade_pending` approval gate; auto-rollback on failure
4. **Update checker extension** — extend `runUpdateCheck()` to scan `plugins` per company; upsert to `marketplacePendingUpdates`
5. **Company Settings → Plugins UI** — rich list with status/version/upgrade badge; `PluginDetailSlideOver` with Overview + Settings tabs; capability delta approval modal
6. **Instance Settings simplification** — strip install/upgrade/config UI; keep diagnostics only

### 1a. `plugins` table

```typescript
// packages/db/src/schema/plugins.ts
export const plugins = pgTable(
  'plugins',
  {
    id: uuid('id').primaryKey().defaultRandom(),
    companyId: uuid('company_id')          // NEW
      .notNull()
      .references(() => companies.id, { onDelete: 'cascade' }),
    pluginKey: text('plugin_key').notNull(),
    packageName: text('package_name').notNull(),
    version: text('version').notNull(),
    apiVersion: integer('api_version').notNull().default(1),
    categories: jsonb('categories').$type<string[]>().notNull().default([]),
    manifestJson: jsonb('manifest_json').notNull(),
    status: pluginStatusEnum('status').notNull().default('installed'),
    catalogItemId: text('catalog_item_id'),   // NEW — nullable; set when installed via marketplace
    installOrder: integer('install_order'),
    packagePath: text('package_path'),
    lastError: text('last_error'),
    installedAt: timestamp('installed_at').notNull().defaultNow(),
    updatedAt: timestamp('updated_at').notNull().defaultNow(),
  },
  (t) => ({
    // OLD: uniqueIndex on pluginKey alone
    // NEW: unique per company
    companyPluginKey: uniqueIndex('plugins_company_plugin_key_idx')
      .on(t.companyId, t.pluginKey),
    statusIdx: index('plugins_status_idx').on(t.status),
  }),
)
```

**Data migration:** For any existing rows, set `companyId` = first company's id from the `companies` table. Use Drizzle's migration file generated by `pnpm db:generate`.

## Section 2: Plugin Loader Refactor

### 2a. `installPlugin()` signature change

```typescript
// server/src/services/plugin-loader.ts

// BEFORE
async installPlugin(opts: {
  packageName: string
  version?: string
  source?: 'npm' | 'local'
}): Promise<DiscoveredPlugin>

// AFTER
async installPlugin(opts: {
  packageName: string
  version?: string
  source?: 'npm' | 'local'
  companyId: string           // NEW — required
}): Promise<DiscoveredPlugin>
```

All callers that invoke `installPlugin()` must pass `companyId`. Current callers:
- `plugin-installer.ts` → `installMarketplacePlugin()` — already has `companyId` from the marketplace route
- Server startup `loadAll()` → loads from DB (companyId already on each row, no need to pass)

### 2b. Plugin registry — company-aware key

```typescript
// server/src/services/plugin-registry.ts (or inline in plugin-loader.ts)

// BEFORE: keyed by pluginKey (string)
private registry: Map<string, RegisteredPlugin>
getByKey(key: string): RegisteredPlugin | undefined

// AFTER: keyed by `${companyId}:${pluginKey}`
private registry: Map<string, RegisteredPlugin>
getByKey(key: string, companyId: string): RegisteredPlugin | undefined {
  return this.registry.get(`${companyId}:${key}`)
}
registerPlugin(plugin: RegisteredPlugin): void {
  this.registry.set(`${plugin.companyId}:${plugin.pluginKey}`, plugin)
}
```

## Section 3: Upgrade Flow

### 3a. `lifecycle.upgrade()` implementation

```typescript
// server/src/services/plugin-lifecycle.ts

async upgrade(
  pluginId: string,
  newVersion: string,
  companyId: string,
): Promise<{ status: 'upgraded' | 'needs_approval'; delta?: string[] }> {
  // 1. Load current plugin row
  const [current] = await db.select().from(plugins)
    .where(and(eq(plugins.id, pluginId), eq(plugins.companyId, companyId)))

  // 2. Save rollback snapshot
  // Note: verify `plugin_rollbacks` table exists in packages/db/src/schema/ — 
  // it was referenced in the existing upgrade route skeleton. Add companyId column if absent.
  await db.insert(pluginRollbacks).values({
    pluginId,
    companyId,
    version: current.version,
    packageName: current.packageName,
    manifestJson: current.manifestJson,
  })

  // 3. Stop existing worker
  await this.workerManager.stopWorker(pluginId)

  // 4. Install new version
  const discovered = await this.loader.installPlugin({
    packageName: current.packageName,
    version: newVersion,
    companyId,
  })

  // 5. Compare capabilities
  const oldCaps = new Set((current.manifestJson as any).capabilities ?? [])
  const newCaps = (discovered.manifest.capabilities ?? []) as string[]
  const addedCaps = newCaps.filter(c => !oldCaps.has(c))

  // 6. Update plugin row with new version + manifest
  await db.update(plugins)
    .set({ version: newVersion, manifestJson: discovered.manifest, updatedAt: new Date() })
    .where(eq(plugins.id, pluginId))

  // 7. Transition state
  if (addedCaps.length > 0) {
    await this.markUpgradePending(pluginId)
    return { status: 'needs_approval', delta: addedCaps }
  }

  await this.load(pluginId)   // starts worker, transitions to 'ready'
  return { status: 'upgraded' }
}
```

### 3b. Auto-rollback on failure

The existing route skeleton at `POST /api/plugins/:pluginId/upgrade` already wraps in try/catch and reinstalls from the rollback snapshot. That instance-level route is migrated to `POST /api/companies/:cid/plugins/:pluginId/upgrade` in M.4. The try/catch + rollback logic is preserved in the new company-scoped route.

### 3c. Approve new capabilities

```
POST /api/companies/:cid/plugins/:pluginId/upgrade/approve
```

- Transitions `upgrade_pending → ready`
- Starts the worker
- Returns `{ status: 'ready' }`

If the user clicks Cancel instead:
```
POST /api/companies/:cid/plugins/:pluginId/upgrade/rollback
```

- Reinstalls from snapshot
- Transitions back to `ready` at old version

### 3d. Update checker — plugin scan

```typescript
// server/src/services/marketplace-update-checker.ts

// After the existing skills scan, add:
async function checkPluginUpdates(
  db: DbClient,
  catalogItems: CatalogItem[],
  companyId: string,
): Promise<void> {
  const installedPlugins = await db
    .select()
    .from(plugins)
    .where(
      and(
        eq(plugins.companyId, companyId),
        eq(plugins.status, 'ready'),
      )
    )

  for (const plugin of installedPlugins) {
    const catalogItem = catalogItems.find(
      item => item.npm?.packageName === plugin.packageName
    )
    if (!catalogItem) continue

    const latestVersion = catalogItem.npm?.version
    if (!latestVersion) continue

    const comparison = compareVersions(latestVersion, plugin.version)
    if (comparison <= 0) continue  // already up to date

    const { inserted } = await upsertPendingUpdate(db, {
      companyId,
      catalogItemId: catalogItem.id,
      itemType: 'plugin',
      currentVersion: plugin.version,
      latestVersion,
    })

    if (inserted) {
      await createNotification(db, {
        companyId,
        type: 'marketplace.plugin_update_available',
        payload: { catalogItemId: catalogItem.id, latestVersion },
      })
    }
  }
}
```

Called from `runUpdateCheck()` once per company, after the skills check.

### 4b. `PluginCardGrid` — 2-column card layout

Cards replace the flat row list. Each card shows plugin identity, description, status, and capabilities at a glance.

```tsx
function PluginCard({ plugin, pendingUpdate, selected, onSelect }) {
  const hasUpdate = !!pendingUpdate

  return (
    <button
      onClick={() => onSelect(plugin)}
      className={cn(
        'relative flex flex-col gap-3 p-4 rounded-xl border text-left transition',
        selected
          ? 'border-indigo-500 bg-indigo-950/20 shadow-[0_0_0_1px_theme(colors.indigo.500)]'
          : 'border-zinc-800 bg-zinc-900 hover:border-zinc-700 hover:shadow-lg',
        hasUpdate && 'border-t-amber-500 border-t-[3px]',
      )}
    >
      {/* Header: icon + name + version */}
      <div className="flex items-start gap-3">
        <PluginIcon plugin={plugin} className="w-10 h-10 rounded-xl text-xl flex-shrink-0" />
        <div className="flex-1 min-w-0">
          <div className="text-sm font-bold text-zinc-100">{plugin.manifest.name}</div>
          <div className="text-xs text-zinc-500">v{plugin.version}</div>
        </div>
      </div>

      {/* Description */}
      <p className="text-xs text-zinc-500 leading-relaxed line-clamp-2">
        {plugin.manifest.description}
      </p>

      {/* Badges */}
      <div className="flex flex-wrap gap-1.5 items-center">
        {hasUpdate && (
          <Badge variant="amber" className="animate-pulse">↑ Update {pendingUpdate.latestVersion}</Badge>
        )}
        <StatusBadge status={plugin.status} />
        {plugin.categories.slice(0, 1).map(cat => (
          <Badge key={cat} variant="muted">{cat}</Badge>
        ))}
      </div>

      {/* Footer: caps + action label */}
      <div className="flex items-center justify-between pt-2.5 border-t border-zinc-800">
        <div className="flex gap-1 flex-wrap">
          {(plugin.manifest.capabilities ?? []).slice(0, 3).map(cap => (
            <span key={cap} className="text-[9px] px-1.5 py-0.5 rounded bg-zinc-800 text-zinc-500">
              {cap.split('.')[0]}
            </span>
          ))}
        </div>
        <span className="text-xs text-indigo-400 font-semibold whitespace-nowrap">
          {hasUpdate ? 'Manage →' : 'Configure →'}
        </span>
      </div>
    </button>
  )
}

export function PluginCardGrid({ plugins, pendingUpdates, selectedId, onSelect }) {
  return (
    <div className="grid grid-cols-2 gap-3">
      {plugins?.map(plugin => (
        <PluginCard
          key={plugin.id}
          plugin={plugin}
          pendingUpdate={pendingUpdates?.find(u => u.catalogItemId === plugin.catalogItemId)}
          selected={plugin.id === selectedId}
          onSelect={onSelect}
        />
      ))}
    </div>
  )
}
```

**Visual design rules:**
- 2-column grid, 12px gap
- Plugin icon: per-category gradient background (notifications → indigo, issues → slate, storage → emerald)
- Update available: amber top border stripe (3px) + pulsing "↑ Update X.X.X" badge
- Selected: indigo border + ring + dark indigo bg tint
- Hover: zinc-700 border + shadow-lg
- Description: 2-line clamp, zinc-500
- Footer label: "Manage →" when update exists, "Configure →" otherwise

## Section 6: Route Changes

### New company-scoped plugin routes

All plugin management routes move to company scope. Add to `server/src/routes/plugins.ts` (or a new `server/src/routes/company-plugins.ts`):

```
GET    /api/companies/:cid/plugins                        — list installed plugins for company
GET    /api/companies/:cid/plugins/:pluginId/config       — get config
POST   /api/companies/:cid/plugins/:pluginId/config       — upsert config
POST   /api/companies/:cid/plugins/:pluginId/upgrade      — trigger upgrade
POST   /api/companies/:cid/plugins/:pluginId/upgrade/approve  — approve new capabilities
POST   /api/companies/:cid/plugins/:pluginId/upgrade/rollback — cancel + rollback
PATCH  /api/companies/:cid/plugins/:pluginId/settings     — toggle enabled (replaces plugin_company_settings PUT)
```

### Existing instance routes — kept for diagnostics

```
GET  /api/plugins                — list all (instance view, health/status only, no config)
GET  /api/plugins/:pluginId      — single plugin detail (health only)
```

Config and upgrade routes at `/api/plugins/:pluginId/config` and `/api/plugins/:pluginId/upgrade` are deprecated in M.4 in favour of the company-scoped equivalents above.

## Testing

- **Schema migration:** Verify existing plugin rows get companyId backfilled; verify unique constraint blocks duplicate `(companyId, pluginKey)`.
- **Plugin loader:** Install a plugin for company A; verify company B cannot see it. Install same plugin for company B; verify both workers run independently.

- **Config form:** Save config for github-issues; verify `plugin_config.configJson` row has correct companyId; verify other company's config is unaffected.
- **Update checker:** Add a plugin row at v0.1.1 when catalog has v1.0.0; run `runUpdateCheck()`; verify `marketplacePendingUpdates` row created with `itemType: 'plugin'`.
