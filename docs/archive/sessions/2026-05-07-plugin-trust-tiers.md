# Plugin Trust Tiers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Persist a `trustTier` column on the `plugins` DB table so the worker sandbox (C2) can read it at spawn time. Value is set from the catalog item at install time and cannot be changed by users.

**Architecture:** Add a nullable `trust_tier` text column (default `'untrusted'`) to `packages/db/src/schema/plugins.ts`, generate the migration, add the type to `PluginRecord`, and read `catalogItem.trust?.tier` in `plugin-registry.ts` on insert.

**Tech Stack:** TypeScript, Drizzle ORM, PostgreSQL, Vitest

**Dependency:** This plan must ship BEFORE the plugin worker sandbox plan (C2) — C2 reads `plugin.trustTier` at spawn time.

---

## Trust Tier Values

| Value | Meaning |
|-------|---------|
| `"untrusted"` | Default for all npm-published plugins. Full sandbox applies in C2. |
| `"verified"` | Signed by AoA marketplace. Looser allowlist in C2. |
| `"core"` | Bundled with the product. No sandbox in C2. |

## Task 2: Verify trustTier defaults and add a manual override endpoint

**Files:**
- Modify: `server/src/__tests__/plugin-trust-tiers.test.ts`
- (No changes to registry needed — DB default handles it)

**Why no registry change:** The current install flow sends `{ packageName, version }` from the UI with no catalog item reference. The `catalogItemId` exists as an optional field in `PluginInstallOptions` but is not wired through the marketplace install flow yet. The DB column default `'untrusted'` correctly assigns the most restrictive sandbox to all newly installed plugins. Mapping `MarketplaceTrustTier` → `PluginTrustTier` from the catalog (`"verified"` → `"verified"`, `"community"` / `"unverified"` → `"untrusted"`) is deferred to a follow-up PR when the install flow is extended to pass `catalogItemId` and the catalog service is accessible inside the plugin routes.
