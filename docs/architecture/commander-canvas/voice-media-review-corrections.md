## M1 — protect the secret at the common resolver

**Owner: E8.1/1 credential foundation.** Propose a dedicated persistent resolutionScope on company_secrets, with constrained values general (existing/default) and voice_media. It is application-owned security metadata, not a client-editable vendor metadata field and not an MCP OAuth identity. The scope applies to every version of the secret. Add its shared validation, Drizzle schema/export/generated migration and authority checks together during approved implementation.

For voice_media, resolveSecretValue checks this classification before legacy exemptions or vendor resolution. Require provider_connection consumer type, nonempty exact capability path, a server-derived authorized actor/company/connection, active secret/connection, accepted current terms/policy and the matching binding. Verify the connection's secretRef equals this secret and its sharing/capability permits this actor and purpose. Claimed context strings alone are insufficient: common resolution must invoke the policy owner, not trust a caller's assertion that authorization happened. Missing or revoked binding, unknown purpose, stale policy or mismatched connection denies and audits. Generic system/plugin/routine contexts cannot resolve these secrets even if they omit configPath. Existing general secrets retain their current legacy behavior.

The new management path creates a dedicated voice_media secret and its initial binding atomically, or explicitly attaches an already restricted secret under its actual sharing authority. Selecting an existing general secret for this capability is refused with a configuration explanation; do not automatically change its scope or copy key material. An admin can configure a separate restricted credential through Secrets. No runtime mutation migrates a key behind existing agent/plugin consumers. Converting an existing shared credential would require an explicit consumer inventory and separately reviewed migration; it is not part of the initial path.

Scope is immutable through ordinary create/update/rotate/import APIs after restricted creation. Generic APIs cannot strip, downgrade, overwrite or recreate the restricted identity to bypass it. Rotation preserves classification; new material remains subject to the same guard. Deleting the last binding or unlinking/deleting a connection leaves the restricted secret restricted and unresolved. No fallback to general resolution occurs. A deliberately authorized new general credential is a separate administrative action, not automatic cleanup behavior.

Binding/connection/secret mutation and resolution must share a documented authority boundary. Reuse the qualified secret/connection policy service to serialize the grant check and credential handoff against revocation; enumerate its create/update/delete/rotate/binding writers and vault-resolution entry points. Already issued credentials require the separate session-stop mechanism; resolver denial cannot recall plaintext previously released. Qualification must prove there is no alternate application resolution/export route for restricted secrets. Direct vault administration is a separate privileged trust boundary, not something caller labels secure.

**Files:** modify packages/db/src/schema/company_secrets.ts; shared secret/connection validators under their verified source owner; server/src/services/secrets.ts and provider-connections.ts; proposed server/src/services/voice-media-credentials.ts. Extend proposed voice-media-credentials.test.ts with the real common resolver, not only a broker mock. No global removal of legacy exemptions and no repurposing assertMcpOAuthResolutionAllowed.

**Required tests:** system/plugin/system-routine/no-path resolution denied for restricted material; general legacy behavior preserved; deleted final binding remains denied; forged consumer/connection/actor denied; revoked connection/capability/terms denied; rotation/import/update cannot remove classification; shared legacy selection produces no migration; concurrent resolve/revoke has a defined authorization order; denied paths call the vault zero times and reveal no plaintext. Complete alternate-entry-point inventory is an enablement gate.

## M2 — shared budget producer and schedule

**Owner: the canonical Budget service, delivered as an explicit prerequisite work package within E8.1/1.** E8 owns delivery coordination, not a second policy authority or a budget editor in Universe. Name this work package BUDGET-VOICE-MEDIA in the existing increment; it does not create another release slice. The actual accountable implementer/reviewer is still unassigned and must be recorded before execution.

Order: BASE and accepted security/schema design → E8.1/1 credential and budget foundations → E3.1/2 session integration and E4.3/2 paid media admission. E3.1/1 may perform documentation and static protocol mapping independently; its paid/live application qualification closes only after these foundations and its session consumer exist. E8.1/2 UI consumes them later. Never require completed voice UI or completed live qualification to build their budget producer. No production path is enabled until atomic admission, durable stops and provider-specific exposure evidence all pass.

Proposed new files owned by this work package:
- packages/db/src/schema/budget_capacity_reservations.ts — company-scoped reservation identity, held capacity and reconciliation state; Drizzle-generated schema/migration with exports and reviewed role/tenant access.
- server/src/services/budget-capacity.ts — transactional admission/extension/settlement under canonical Budget policy, called by budgets.ts or its authorized consumer facade.
- server/src/__tests__/budget-capacity.integration.test.ts — concurrent transactions and canonical cost-writer integration.

These are proposed paths, not existing APIs. Existing budgets.ts, canonical cost posting/evaluation and their actual writer routes remain the policy/accounting authority. Before coding, pin their complete writer inventory, exact tenant transaction/role, charge attribution and lock order in this producer's bounded plan. If that inventory cannot establish participation for spend sharing a hard cap, report the gap and keep admission unavailable; a voice-only reservation cannot protect a company budget from other bypassing spend.

**Producer contract:** reserve or extend capacity using company, applicable canonical budget scopes, immutable operation identity and maximum admitted cost; observe reservation; settle against canonical charge identities; cancel/release only proven unused exposure. A reservation is a hold, not a second cost event. Bind all applicable company/agent/department caps without treating the same held amount as several actual charges. Reject a changed payload under an existing operation key. Return typed admitted/denied/unknown outcomes, never a bare unchecked boolean.

**Atomicity:** serialize admissions and relevant policy/charge updates on a stable company budget authority row, with any subordinate scope locks in a fixed order established against current writers. Under that same transaction, compute canonical posted cost plus outstanding, non-double-counted exposure, check each applicable cap and persist the hold. Voice session creation and its hold commit together before vendor admission. Media persists its canonical operation and hold through its actual E2/E4 producer; no parallel generation queue. All competing paths must consume this authority or have an explicitly proved bound included in admission. An in-memory mutex or a check followed by a separate insert is insufficient.

**Charging and termination:** reserve a finite maximum billable exposure using the qualified tariff, duration/output limits and termination latency. Streaming extensions require another atomic admission before the allowed window is consumed; stop early enough that the remaining hold covers the qualified shutdown tail. If a provider cannot establish a bound, that transport stays unavailable. Usage events settle idempotently against their canonical charge IDs, consuming the corresponding hold without counting the same amount twice. Definitive no-effect rejection can release a hold; crash, timeout, lease expiry or missing final invoice cannot. A stopped session may retain a budget hold until final billing reconciles. Account for pending reservations when rolling billing windows; crossing a month cannot erase exposure.

**Durable stops:** budget exhaustion, revoked policy and failed extension persist a stop request in the owning durable session/operation record in the authoritative transaction, with idempotent consumption and an owner recovery path. Local EventEmitter notification is only a wake-up optimization. Multi-server owner restart must observe the persisted stop before resuming work. Budget producer exports the stop decision; voice/session-registry and voice/budget-lifecycle consume it. Media cancellation must use its real canonical operation owner. Lock ordering with these consumers and canonical cost writers requires contention tests; no deadlock-free claim is made from this outline.

**Required tests:** two simultaneous admissions against insufficient shared remaining balance; same operation replay/conflict; voice and media competing; canonical non-voice charges/policy changes racing admission; reported usage settling once; missed local event and process restart; extension denial; late invoice after confirmed stop; unknown admission after crash; billing-period rollover; refund/correction handling under canonical policy; no premature release on lease expiry. No paid provider qualification begins without separately approved spend and these application safety prerequisites.

## L1 — database-enforced voice ownership

**Owner: E3.1/2**, in proposed universe_voice_sessions schema, voice/session-registry.ts and voice-session-authority.integration.test.ts. Proposed non-null state is constrained to reserved, starting, connected, reconnecting, ending, unknown, ended or rejected. Add nullable terminalAt and a database check making terminalAt non-null exactly when state is ended or rejected. Unknown never counts as terminal.

Two independent unique indexes are required:
- (companyId, userId, startRequestId) for immutable request identity across all outcomes.
- (companyId, userId) WHERE terminalAt IS NULL for one unresolved session across devices/tabs/providers in the company.

Use the repository's Drizzle uniqueIndex(...).where(...) pattern and generated migration, not handwritten index DDL. Confirm company/actor types and composite tenant access before coding. Required identifiers are non-null; no nullable user key can bypass uniqueness. This tightens the old per-user/device wording in E3.1/2.

**Start transaction:** server authenticates the actor and scope; obtains the canonical budget authority locks; handles same-start identity replay/conflict; reserves budget and inserts the reserved session atomically. Concurrent distinct starts cannot both commit due to the active-owner index. Translate that conflict to the current authorized session/busy outcome without a provider call; do not turn a uniqueness error into a blind retry. Only a fenced owner may claim reserved → starting and perform the external start after commit. Record that transition before the call. A recovered starting/unknown attempt is reconciled, not reissued; only a proven not-issued reserved attempt can be claimed for first issuance.

**Owner fencing:** use lease owner plus monotonic generation for conditional updates and callback association. Lease expiry allows recovery of the same session record, not a second active session or repeat network start. The provider-side stop/reconciliation proof remains necessary because a database fence alone cannot stop an old external connection.

**Takeover:** mark the existing session ending and persist its stop request, then perform provider shutdown outside the transaction. Keep its ownership slot while outcome is uncertain. Only confirmed termination (ended), or definitive proof no provider session was created (rejected), sets terminalAt. Local mic stop alone is not confirmation. A new explicit start can then compete for the released slot. Do not hold database locks while waiting on a vendor. Delayed events for a terminated generation cannot reopen it; a new session uses a new start identity. Final charges may remain unresolved after ownership is released, and their budget reservation remains held independently.

**Required tests:** simultaneous tabs/devices/providers; duplicate and conflicting start key; crash before issuance versus after starting persisted; lost vendor ACK; lease expiry with old transport still alive; competing takeovers; callback after takeover; terminal/state constraint mismatch; null identity rejection; delayed billing after confirmed end. These must run against the real PostgreSQL schema and transactional budget/session producers after implementation approval, not just mocked controllers.
