## Contract

Proposed exported service `universeStateService(db)` has `get(scope)`, `apply(scope, patch)` and `getReceipt(scope, operationId)`, plus `getCheckpoint(scope,key,sourceVersionId)` and `saveCheckpoint(scope,key,input)` as specified below. `scope={companyId,userId,conversationId}` is derived from authenticated request and canonical conversation ownership, not body-supplied actor fields. V1 personal layout writes are owner-only even when another user can read a shared conversation. Register GET/PATCH `/api/companies/:companyId/universe/conversations/:conversationId/layout` and GET `.../layout/operations/:operationId`. Missing/inaccessible conversation returns the existing not-found convention; invalid operation 400, stale revision or reused ID/content mismatch 409.

```ts
export type LayoutOp =
  | { type:'open'; key:string; ref:{kind:string;id:string;version?:string}; rect:Rect }
  | { type:'geometry'; key:string; rect:Rect }
  | { type:'pin'; key:string; value:boolean }
  | { type:'minimize'; key:string; value:boolean }
  | { type:'close'; key:string }
  | { type:'order'; keys:string[] }
  | { type:'presentation'; selected:string|null; maximized:string|null }
  | { type:'viewport'; x:number; y:number; zoom:number };
export type Rect = {x:number;y:number;width:number;height:number};
export type LayoutPatch = {schemaVersion:1;operationId:string;expectedRevision:number;operations:LayoutOp[]};
export type LayoutAck = {operationId:string;revision:number;schemaVersion:1;
  opened:Array<{operationIndex:number;key:string;openedOrdinal:number}>;nextOpenedOrdinal:number};
```

Use a strict discriminated Zod union; `kind` must be the accepted reference-kind enum, not arbitrary render code. Ref authorization is checked before inclusion/preview; no content bodies, credentials, raw audio, cookies or live control tokens in layout. Proposed initial transport bounds: 200 records, 50 operations/patch, 64 KiB patch, 256 KiB snapshot, finite coordinates within ±1,000,000 and dimensions 1–8192 canvas units. Zoom 0.25–2 follows the reference controller; bounds require host qualification, not capacity claims.

### Complete layout write/read contract

GET returns E1.1's `AuthorizedLayoutSnapshot`, including `viewport:{x,y,zoom}`. Store CSS-pixel camera translation x/y within ±1,000,000 and zoom 0.25–2 separately from canvas-unit panel rectangles. A missing layout returns an authorized revision-zero snapshot with counter 1, default camera {x:0,y:0,zoom:1}, empty panels/order and null selected/maximized; GET creates no row. Resolve authorized reference titles at read time rather than trusting client-supplied display text.

Apply operations in input order to a transaction-local candidate; publish only after final invariant checks. Preserve these semantics across the server applier and E1 controller:

| Operation | Candidate-state effect |
|---|---|
| open | Validate key equals the scoped canonical reference key; new panel gets supplied normal rect and next ordinal. Existing panel keeps normal rect/ordinal, becomes visible and foreground. Both select it, move it to end of order and exit another panel's maximized mode, matching E1.1 foreground. |
| geometry / pin | Update only that field on the existing panel; geometry cannot modify a minimized/maximized target. Presentation does not imply execution permission. |
| minimize true | Hide target; clear maximized if it names target; if selected target, select last visible panel in order or null. Retain normal rect, ordinal and order membership. |
| minimize false | Restore target in normal mode, foreground/select it and clear maximized, matching E1.1 restore. |
| close | Remove only target and its order entry; clear its maximized state and choose next visible selection when necessary. No checkpoint, draft, task or artifact deletion. |
| order | Set the full z-order permutation; never rewrite ordinals or infer selection from an arbitrary order change. |
| presentation | Explicitly set selected/maximized as one pair. Non-null selected must exist and be visible; non-null maximized must equal selected and be last in order. Maximize is sent after any required restore/order operation, in the same patch. Null maximized restores normal display without changing normal rect. |
| viewport | Set only validated camera x/y/zoom; no geometry or focus change. User camera movement is disabled while maximized by the controller; a save batch may include a completed pre-maximize camera change followed by maximize. Persist that camera so restoring from maximize returns to it; do not infer an unauthorized live gesture merely from the final maximized state. |

Require final order to contain every existing panel exactly once, including minimized panels; no missing, foreign or duplicate keys. Validate the selected/maximized pair and geometry/camera bounds on the whole candidate. Invalid patches return 400 without any partial write, receipt or audit. Failed expectedRevision or reused operation identity remains 409. Transient intermediate presentation mismatch while composing restore/order/presentation is allowed only inside the atomic candidate; no invalid state becomes externally visible.

E1.2's UI adapter batches a focus change as order + presentation; maximize as visibility restoration if needed + order + presentation; restore from maximize as presentation with maximized null and preserved normal rect, and restore from minimize as minimize(false) plus final order/presentation if needed. The adapter records affected presentation fields together for conflict handling. Camera, order, selection and maximize writes participate in the same expectedRevision/operationId receipt protocol as geometry, not a second unfenced save endpoint. Safe rebase additionally validates the entire candidate: selection/maximize/order form a coupled conflict group, and camera plus maximize must remain compatible. If concurrent changes violate these rules, retain the local candidate and require resolution rather than overwriting it.

## E1.2/2 — Conflict and reload recovery

- [ ] `useUniverseState` retains acknowledged snapshot separately from optimistic operations. Debounce transient geometry (proposed 250 ms), flush final gesture immediately, and show saving/saved/offline/conflict based on server acknowledgement, never local animation.
- [ ] On lost ack query the operation receipt first. If absent, fetch snapshot. Rebase only property changes whose base property is unchanged; same-property edits preserve local candidate and require explicit resolution. Resubmission uses a new operationId only after resolving the old operation's outcome and recomputing expectedRevision.
- [ ] Keep receipts for the life of the layout initially; do not add arbitrary TTL that permits old IDs to apply twice. Later retention needs tombstone/expiry semantics and measured storage review. Bound the client pending journal (100 patches/1 MiB proposed); on overflow stop enqueueing and preserve a downloadable/recoverable local snapshot rather than falsely showing saved.
- [ ] Reload restores the authoritative nextOpenedOrdinal/panel ordinals before new opens; optimistic receipt reconciliation updates only the matching open incarnation. Checkpoints load separately by exact source version; never embed them in whole-layout patches. Close retains checkpoint/draft data under its retention policy, new source versions get separate state, and appearance reset never clears it.
- [ ] Reload fetches authorized snapshot before rendering cached previews. A smaller viewport computes display clamps without persisting them as preferred geometry. Logout/company switch cancels in-flight requests and clears accessible cached data; offline local retention follows explicit policy, not an assumed secure browser store.
