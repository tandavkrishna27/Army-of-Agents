# E4.3 — Immutable revisions and generation implementation plan

> **For agentic workers:** Use superpowers:executing-plans after TK explicitly approves implementation. This plan does not authorize provider sessions, dependency installation, branch changes or coding.

**Goal:** Inspect, compare, refine and export immutable artifact versions, and reconcile generated results without duplicate publication or spend.

**Architecture:** Reuse `artifacts`/`artifact_versions` and canonical request/job output authority. Add only version-concurrency/idempotency and explicit winner-selection support missing from source. Generated bytes enter E4.1/E4.2 validation/publication before they are represented as ready output.

**Tech stack:** Existing TypeScript, Drizzle/PostgreSQL, asset storage and React viewers; generation adapters/writers require separate qualification.

**Spec:** [E4.3 outline](../slice-plans/e4-3.md), [artifact contract](../artifact-contract.md), [format matrix](../format-matrix.md), [request contract](../request-contract.md), [U04/U06/U09/U10](../ui-review-decisions.md). Both increments are V1.

## E4.3/1 — Immutable revisions

**Modify:** `packages/db/src/schema/artifacts.ts`, `server/src/services/artifacts.ts`, `server/src/routes/artifacts.ts`, verified `packages/shared/src/validators/artifact.ts:createArtifactVersionSchema`, and `ui/src/api/artifacts.ts`. **Create:** `packages/shared/src/validators/universe-artifact-versions.ts`, `ui/src/components/universe/ArtifactVersions.tsx`, `server/src/__tests__/universe-artifact-revisions.test.ts`, `tests/e2e/universe-artifact-revisions.spec.ts`. Export new schemas through shared indices. Canonical version service remains the single writer for human, agent and MCP paths.

Proposed additive nullable `publicationKey` (text, ≤200) on artifact_versions, unique `(artifact_id,publication_key)` where non-null, and `publicationPayloadHash` (64-hex). Retain existing sourceActionId meaning; never overload it with arbitrary UUIDs. Add `revision` integer default 1 to artifacts for winner CAS. Generate migrations; existing rows remain valid with null publication key/revision 1. No rewrite of prior versions/hashes or source attribution.

```ts
export interface ArtifactVersionSelection {
  artifactId: string;
  selectedVersionId: string; // view/context, never a pointer mutation
  currentVersionId: string | null; // canonical winner/current pointer
  artifactRevision: number;
}

  key: string; payloadHash: string;

export interface SelectCurrentVersionInput {
  versionId: string; expectedArtifactRevision: number;
```

Manual caller publication key uses stable user action identity retained until a terminal response. Generated key is server-derived from canonical accepted output identity, not client supplied. Exact canonical fields bind to E2.2's producer; key encoding must be versioned and collision-free (canonical JSON digest, not delimiter concatenation). Reused key with altered content returns 409, never overwrites or returns misleading success.

E2.2's `SubmissionOutcome` is a turn observation (`clientSubmissionId`, `userMessageId`, `replyMessageId`, `runId`); none is itself a unique artifact output. For existing `ShowRef {kind:'artifact',id,versionId}`, read it from the explicitly linked persisted reply's `outputRefs`, verify artifact/version ownership and reuse that version directly—do not create a second version to “publish” an already published result. `server/src/services/internal-agent/output-refs.ts` can emit nullable versionId and best-effort refs. Missing artifact/version identity must be repaired by the owning result producer from the immutable commit record, never by selecting current/latest version, message order, array index or run ID. A referenced artifact with no exact generated version remains a navigational reference and cannot close generation publication.

For newly generated worker bytes not yet represented as an AoA artifact, publication key derives from verified committed `job_artifacts` identity (organization/job/attempt/identifier plus committed row ID/hash as defined in the worker-publication addendum; fence is provenance, not the publication key), source version and requested output slot. Bind exact exported protocol identity with DAT/CMD owner before coding; if its stable committed identity is unavailable, output-to-version integration remains blocked. The worker's versionNumber is a best-effort ordinal, not an artifact_versions identity. The common publication receipt also deduplicates first artifact creation, which a per-artifact unique key alone cannot protect. After one atomic application publication, persist artifact/version reference in the linked reply/outputRefs or durable canonical result projection. Do not wait for best-effort notification to establish publication.

Representative HTTP test uses actual fixture `seedCompany` and canonical routes; new parameters are proposed:

```ts
import { expect, test } from "@playwright/test";
import { randomUUID } from "node:crypto";
import { seedCompany } from "./helpers/seed-company";

test("repeated version publication returns one immutable version", async ({ request }) => {
  const company = await seedCompany(request, `E2E-Universe-Version-${Date.now()}`);
  const created = await request.post(`/api/companies/${company.id}/artifacts`, {
    data: { title: "Plan", type: "document", source: "founder", content: "v1" },
  });
  expect(created.ok()).toBeTruthy();
  const artifact = await created.json();
  const body = { source: "founder", content: "v2", parentVersionId: artifact.versions[0].id,
    publicationKey: randomUUID() };
  const first = await request.post(`/api/artifacts/${artifact.id}/versions`, { data: body });
  const second = await request.post(`/api/artifacts/${artifact.id}/versions`, { data: body });
  expect(first.ok()).toBeTruthy(); expect(second.ok()).toBeTruthy();
  expect((await first.json()).id).toBe((await second.json()).id);
  const reread = await request.get(`/api/artifacts/${artifact.id}`);
  const result = await reread.json();
  expect(result.versions).toHaveLength(2);
  expect(result.versions.find((v: { content: string }) => v.content === "v1")).toBeTruthy();
});
```

## E4.3/2 — Generation qualification

**Files:** Create `docs/architecture/commander-canvas/generation-qualification.md` at execution evidence stage, `server/src/services/universe-generation.ts`, `server/src/__tests__/universe-generation-outcomes.test.ts`; extend E4.2 registry with independently qualified native writers; create `ui/src/components/universe/ArtifactGenerationStatus.tsx`. Do not create a second jobs/outcomes table. If canonical output cannot bind exactly once to a version, add the linkage to its owning replatform repository with owner review, not a shadow canvas queue.

Planned internal boundary (not an invented vendor SDK):

```ts
export type GeneratedOutputDecision =
  | { state: "not_submitted" }
  | { state: "pending"; clientSubmissionId: string }
  | { state: "unknown"; clientSubmissionId: string; retryAllowed: false }
  | { state: "failed"; clientSubmissionId: string; retryAllowed: boolean }
  | { state: "published"; clientSubmissionId: string; replyMessageId: string;
      artifactId: string; versionId: string };
```

`universe-generation.ts` projects canonical outcome into this union and publishes only verified completed output via E4.1/E4.3/1. It does not infer success from notification, live stream or tool-channel delivery. Execution admission, budget reservation, cancellation and job fencing stay with canonical owners. Status GET/reconnect and preview retry have no submission capability.

- [ ] Define regression cases before adapters: lost submission ACK, accepted but timed out provider, cancelled yet late output, completed original with preview failure, duplicate worker event, source version changed while generating, permission revoked before publication, and publication failure after successful paid generation. Only an authoritative “not accepted/no effect” or a user-approved new attempt after disclosed uncertainty can permit another billable submission.
- [ ] Bind canonical request ID, accepted job/attempt/output identity and outcome query to E2.2. Pin generation inputs to selected immutable source IDs/hash. Persist output-to-version linkage atomically with version creation under publication key. Worker outputs that have not passed fenced commit/validation remain pending or rejected, never ready artifacts.
- [ ] Implement deterministic document/deck/workbook/PDF/chart writers as separate registry capabilities after fixture reopening; media image/audio/video generation adapters qualify separately. Native export is not external sharing. Export original may be read-only; creating a new export is governed processing; publication to an external service is a separately named, explicitly authorized action.
- [ ] Surface admitted/running/checking outcome/file ready/preview failed/failed/denied states without fabricated progress. Unknown shows “Checking whether the output was created” and no one-click blind retry. Closing/minimizing leaves canonical generation active; explicit cancel reports whether bytes/version already exist. No auto-camera movement on background completion.

Qualification is a blocking contract, owner unassigned, and requires these inputs for **each** provider or deterministic writer: exact package/API/model/build, license/terms, credential reference owner and runtime-key policy allowance, permitted region/retention/deletion behavior, input/output schema, maximum sizes/duration, cost/rate limits, idempotency or status-lookup semantics, cancellation guarantees, native-format validator and fixture manifest.
