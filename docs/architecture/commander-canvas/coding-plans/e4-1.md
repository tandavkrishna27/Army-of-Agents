**Policy reconciliation:** Pinned Decision #122 and AGENTS/CLAUDE permit narrowly conditioned idempotent security DDL in delta-free custom migrations because the generator cannot emit it. Older session-supplied AGENTS text lacks this class. The [shared binding record](../implementation-bindings.md#contract-compatibility-decisions) captures the difference. Reconcile applicable execution instructions and bind the locked decision before migration work; table/column/index/FK DDL remains generated. Do not interpret the conditional gate below as proof no supported security-migration path exists.

> **For agentic workers:** Use superpowers:executing-plans only after TK explicitly approves implementation of the reviewed packet. This is documentation, not permission to implement, run qualifications, install packages or create branches.

**Goal:** Preserve and recover an authorized original independently of its preview, extraction and generation status.

**Architecture:** Extend the canonical asset intake boundary with resumable, actor-bound transfer records. Publication creates an `assets` record; attaching it to a composer or promoting it to an artifact remains a separate authorized operation. Worker output continues through the replatform fenced artifact-commit authority.

**Tech stack:** Existing TypeScript/Express/Drizzle/PostgreSQL, storage providers, React and shared validators.

**Spec:** [E4.1 outline](../slice-plans/e4-1.md), [artifact contract](../artifact-contract.md), [master scope §8](../master-scope.md), [U04/U06/U09/U10](../ui-review-decisions.md), [reset](../planning-reset.md). Both original increments below are V1.

## Proposed interfaces and storage ledger

Create `packages/shared/src/validators/universe-intake.ts` and export through shared validator/root indices. Names below are proposed public contracts, not existing exports:

```ts
export type IntakeDestination =
  | { kind: "canvas"; conversationId: string }
  | { kind: "commander_attachment"; conversationId: string }
  | { kind: "discussion_attachment"; discussionId: string };
export type IntakeState = "receiving" | "validating" | "publishing"
  | "published" | "cancelled" | "expired" | "rejected";
export interface IntakeSnapshot {
  intakeId: string; revision: number; state: IntakeState;
  receivedParts: number[]; expiresAt: string;
  assetId: string | null;
  reason: "type_mismatch" | "too_large" | "hash_mismatch" | "access_revoked" | null;
}
```

Zod schemas are strict: UUID references, UUID client key, filename 1–255 characters, lowercase 64-hex hash, safe integer positive byte size, no client actor/company/storage keys. Destination is resolved and checked before accepting bytes and before commit; `canvas` accepts only an owned Commander conversation. Composer variants apply the existing allowlist and count/size at attachment binding, not merely at upload. Ordinary `canvas` assets never earn `composerValidated` by being opened in a composer.

Task composer files are a fourth user-visible intake path delegated to the existing task authority, not silently converted to generic canvas assets. E1.3/E2.4 use the verified `issuesApi.addCommentWithAttachments(id,body,files,reopen?,interrupt?,clientSubmissionId?)` → `POST /api/issues/:id/comments-with-attachments`, returning `{comment,attachments}`. Preserve that atomic comment/attachment and task authorization path; its File/reselect recovery and submission ID belong to E1.3. `IntakeDestination` above intentionally covers only asset-ledger intake; “Attach to Task” invokes the existing task adapter and labels its destination. Extending task submission to accept resumable asset references requires a separately reviewed canonical task-route change, not broadening this union alone.

Create `packages/db/src/schema/universe_intakes.ts`: `universe_intakes` fields `id`, `organization_id`, `company_id`, `actor_key` (server-derived), `client_key`, `payload_sha256`, `destination` JSON, `filename`, `declared_content_type`, `byte_size`, `sha256`, `state`, `revision` default 1, `asset_id` nullable FK, `expires_at`, timestamps; unique `(company_id,actor_key,client_key)`. `universe_intake_parts` fields intake/company/organization IDs, `part_index`, server-generated `object_key`, `byte_size`, `sha256`, `state` (`reserved`/`stored`), primary `(intake_id,part_index)`. These are application-scoped tables under selected A. organization_id is derived from the authorized company for existing storage routing/integrity, never an authorization substitute or a client-supplied scope. No intake table is added to the frozen distributed RLS registry. Part reads/writes validate the authenticated intake owner and matching company through the parent; foreign part IDs cannot bypass that predicate. Reserve every storage object key durably before writing it. Add final-object reservation to intake (`final_object_key`, `final_byte_size`, `final_sha256`) before final put. Create `server/src/services/universe-asset-access.ts:assertUniverseAssetAccess` and invoke it from existing `assetRoutes` metadata/content/render handlers after company authorization and before storage/metadata output. Representative integration recipe using the repository's actual e2e `seedCompany` fixture (new route and proposed UUID key):

```ts
import { test, expect } from "@playwright/test";
import { createHash, randomUUID } from "node:crypto";
import { seedCompany } from "./helpers/seed-company";

test("lost finalize response resolves to one original", async ({ request }) => {
  const company = await seedCompany(request, `E2E-Universe-Intake-${Date.now()}`);
  const conv = await request.post(`/api/companies/${company.id}/internal-agent/conversations`, { data: {} });
  expect(conv.ok()).toBeTruthy();
  const conversation = await conv.json();
  const bytes = Buffer.from("Original text\n", "utf8");
  const hash = createHash("sha256").update(bytes).digest("hex");
  const base = `/api/companies/${company.id}/universe/intakes`;
  const begin = await request.post(base, { data: {
    clientKey: randomUUID(), destination: { kind: "canvas", conversationId: conversation.id },
    filename: "source.txt", contentType: "text/plain", byteSize: bytes.length, sha256: hash,
  }});
  expect(begin.status()).toBe(201);
  const { intakeId } = await begin.json();
  const part = await request.put(`${base}/${intakeId}/parts/0`, {
    data: bytes, headers: { "content-type": "application/octet-stream", "x-part-sha256": hash },
  });
  expect(part.ok()).toBeTruthy();
  const first = await request.post(`${base}/${intakeId}/finalize`);
  const second = await request.post(`${base}/${intakeId}/finalize`);
  expect(first.ok()).toBeTruthy(); expect(second.ok()).toBeTruthy();
  const a = await first.json(); const b = await second.json();
  expect(a.assetId).toBe(b.assetId);
  const downloaded = await request.get(`/api/assets/${a.assetId}/content`);
  expect(await downloaded.body()).toEqual(bytes);
});
```

## Limits, qualification, rollback and closure

Proposed, unmeasured limits: 4 MiB chunks, total `min(AOA_FILE_MAX_BYTES, 50 MiB)` initially; composer still ≤10 MiB; 2 simultaneous transfers/user and 8/company; 500 MiB reserved temporary bytes/company; 24-hour receiving expiry, sweeper every 15 minutes, 7-day idempotency tombstone after cleanup. 2-minute finalize lease with fencing revision; no automatic whole-upload retry. Larger than 50 MiB is a visible limit, not a promised supported large-file path. Reservation admission must be transactional so parallel callers cannot exceed quotas. Keep canonical files under existing retention policy; expiry never deletes a published original. These defaults require capacity/security review, owner unassigned.
