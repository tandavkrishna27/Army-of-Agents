# E6.3 Remote local-browser access implementation plan

> **For agentic workers:** Use `superpowers:executing-plans` only after explicit implementation approval. Worker registration, local capture and remote sessions are not run during planning.

**Goal:** Access an authorized local worker's browser from another device while preserving browser-only scope, control fencing and honest offline state.

**Architecture:** The local worker initiates an authenticated outbound connection; authorized clients attach through the qualified relay. It consumes the same session/control descriptor as cloud, with local capabilities stated independently. Local computer availability is not a new browser session or an automation resume.

**Tech stack:** Existing worker identity/connection infrastructure and TypeScript UI; exact capture/relay protocol and OS bindings are E6.0/3 qualification outputs.

**Spec:** [E6.3](../slice-plans/e6-3.md), [E6.0/3](e6-0.md), [E6.1](e6-1.md), [E6.2 control contract](e6-2.md), [integration §2](../integration-contracts.md), [settings](../settings-contract.md), [UI](../ui-review-decisions.md).

## E6.3/1 — Remote local-worker access

**Consumes:** E6.0 qualified browser-only transport, worker availability/auth and E6.1 authorized descriptor. **Produces:** Local connection presentation and the same E6.0 epoch/revision-bound view/input envelope as cloud. Proposed availability projection:

```ts
export type LocalBrowserAvailability =
  | { state: "checking"; workerId: string }
  | { state: "online"; workerId: string; browserSessionId: string; protocolVersion: string }
  | { state: "offline"; workerId: string; lastSeenAt: string | null }
  | { state: "unavailable"; workerId: string; reason: "permission" | "unsupported" | "ended" };
```

An `online` worker is not a live session until the authenticated session handshake confirms it. `lastSeenAt` is a stale display fact, not input permission. Server derives worker/company/user association from its canonical identity.

- [ ] **1. Bind outbound worker connection.** Copy exact worker registration/identity, allowed scopes, protocol version, token/certificate expiry/revocation and outbound relay operations from E6.0/3. Record which owner admits viewer versus controller. Do not reuse an API token solely because it has a company ID. Local worker must not receive host/operator/cross-company secrets through this feature. If no approved stream identity exists, leave the capability unavailable and keep runtime binding blocked.
- [ ] **2. Write real two-device authorization scenarios.** A1 on local machine L owns admitted task T1/browser S1; A1 on remote device R may view after current task permission. A2 view-only cannot control; B1 and an unregistered device receive no metadata/frame. Test guessed worker/session IDs, wrong task, revoked user, expired relay credential, replayed token and unsupported worker version. Assert denial before local worker media/input call, not only disabled UI.
- [ ] **3. Implement scoped attachment.** Resolve availability, authorize session view, connect only the selected browser surface and render the canonical task/account/local-machine/controller header. Device name is authorized metadata. UI reports checking/connecting/online/offline/ended distinctly. BrowserChrome/nativeDialogs/audio flags come from local qualification; unsupported features remain disabled. Capture failure cannot fall back to whole-desktop capture.
- [ ] **4. Wire the common control gate.** Use E6.2's requested/acknowledged epoch and fresh page/frame gates; worker checks them again at execution. Local Take control pauses automation before ack; Resume explicitly fences human input and re-observes state. Quality preference requests a supported negotiated stream quality; local worker resource and company policy remain authoritative. No state transition relies on selecting the local panel.
- [ ] **5. Run live boundary proof.** With a visible decoy in a non-browser application, remote R performs fixture navigation, tab switch, harmless form entry and download in S1. Verify decoy is absent from captured media and remote keyboard cannot control the other app. Open another task session S2 and confirm disjoint epoch/input. Exercise native dialog, browser chrome and audio only if advertised; record positive and negative evidence. Repeated minimize/reopen is one underlying session with clean viewer cleanup.

**Recovery:** A denied attach leaves no residual media or remote-input listener. Offline copy says local computer/worker unavailable and preserves canonical task links; it does not invite an unapproved cloud fallback. Failed quality negotiation retains prior effective quality visibly. Unknown capabilities fail unavailable until requalified. Connected input works only on the selected browser surface, with no implicit desktop-control expansion.

## E6.3/2 — Offline and focus recovery

**Consumes:** Current session lifecycle/controller, worker liveness transport, E6.2 input state and E2 read-only canonical outcomes. **Produces:** Disconnect/reset behavior and explicit same-session reconciliation. Proposed `canResumeLocalView(previousSessionId: string, currentSessionId: string | null, workerAuthorized: boolean): boolean` returns true only for nonnull equality and current worker authorization; this is a UI guard, not server auth.

- [ ] **1. Write the identity regression.** Place in the new availability test file:

```ts
import { expect, it } from "vitest";
import { canResumeLocalView } from "./local-browser-availability";
it("never labels a replaced or unauthorized browser as resumed", () => {
  expect(canResumeLocalView("s1", "s1", true)).toBe(true);
  expect(canResumeLocalView("s1", "s2", true)).toBe(false);
  expect(canResumeLocalView("s1", null, true)).toBe(false);
  expect(canResumeLocalView("s1", "s1", false)).toBe(false);
});
```

- [ ] **2. Implement loss teardown.** On stream/auth/worker disconnect disable input, invalidate local epoch acknowledgement, release pointer capture, clear held keys/buttons and drop queued inputs. A best-effort release message may clean up the still-live worker, but cannot be relied on after disconnect; worker-side session expiry must also clear modifiers. Never replay old key-down/click on reconnect. Show cached frame as stale or clear it on revoked access; do not show live status from a recent heartbeat.
- [ ] **3. Reconcile before reconnect.** Reauthenticate current device/user/company, query actual worker availability and browser lifecycle, verify exact session/process identity and controller epoch, reauthorize view, then negotiate fresh media. If same browser is proven live, restore view; input still requires current acknowledged ownership and fresh frame. If ended/replaced, show ended/new-session distinction. Pending external effects use E6.1 canonical outcome inspection before further action.
- [ ] **4. Run failure matrix from both devices.** Drop network while holding a key; unplug/suspend L; restart worker without browser; close browser while worker stays online; revoke worker credential; expire viewer credential; switch company on R; disconnect during takeover ack; reconnect after a new browser was created. Expected no stale input, no lost modifier stuck in OS, no false resume, no new task/session unless explicitly admitted. Record local process IDs only in restricted qualification evidence, session/epoch timelines and fixture counters; no credential content.
- [ ] **5. Run focus/interaction matrix.** Move pointer outside panel while dragging, blur R, press Escape, release key outside browser frame, minimize browser, use 200% text zoom/host zoom and resize to narrow viewport. Canvas must not consume remote typing or wheel intended for browser; local app/system shortcuts not supported by capture remain explicitly unavailable. Keyboard-only users can leave browser input mode and reach End/control actions without a trap. Reduced motion changes transitions only; it cannot postpone disconnect/input disable.

**Commands after approval/tests:** `pnpm exec vitest run ui/src/components/universe/local-browser-availability.test.ts`; `pnpm exec playwright test --config=tests/e2e/playwright.config.ts tests/e2e/universe-local-browser.spec.ts`. Pure identity helper test initially fails until module exists; full tests need the accepted real worker/capture transport. App E2E can inject network loss, but native capture/focus/device sleep needs qualified supported OS evidence. Existing Windows embedded-Postgres skips do not excuse local Windows capture tests; run UI/server fixtures on supported DB/Linux and record platform protocol separately.

## Limits, logging, rollback and self-review

Proposed live-channel liveness timeout is five seconds, distinct from the existing 300,000 ms placement heuristic; security/platform reviewer must choose and measure the actual negotiated value before implementation. Input is disabled immediately on known loss rather than waiting for timeout. Proposed reconnect attempts remain explicit/user-driven; no automatic new browser/session. Source browser TTL bounds in E6.0 remain unchanged and cannot be prolonged by media heartbeat.

Log safe worker/session/company/task/controller/revision references, auth/liveness reason and disconnect/reconnect timing. No desktop pixels, raw keystrokes, cookies or relay credentials in metrics. Worker disconnect can leave an already-running effect unknown; preserve it for canonical recovery. Rollback denies new local attachments, revokes existing relay input, closes viewer resources and leaves cleanup to the canonical execution owner, without killing unrelated local processes or deleting outputs.

Self-review maps both increments and fixes worker-online/live-input equivalence and implicit whole-desktop fallback. Open bindings: local worker authenticated outbound media/capture API (E6.0/3), BROWSER and APPROVAL; reviewers unassigned. PROFILE applies when saved logins are used, not to the signed-out capture-only test. All local access remains V1 and cannot be certified from cloud results. No runtime/provider/install operation occurred for this addendum; full Linux checks plus actual local qualification remain future evidence.
