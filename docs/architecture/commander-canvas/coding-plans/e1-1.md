## Verification and limits

Use the exact unit/frame/workspace/E2E commands in the reference plan. Add `panel-history.test.ts` with undo after close/reopen, undo of pinned human move and refusal to replay old generation. Browser journeys must exercise 0.5/1/2 camera zoom, unmeasured viewport and narrow bounds, including all entry points from E1.0/E2.4.

Bounds and timings in the reference module are initial engineering choices, not measured performance guarantees. Performance qualification records frame/pointer latency at 1, 10 and 50 panels; above the measured rendering budget suspend hidden expensive content, preserving canonical registry/drafts. Reject excessive persisted counts via E1.2 instead of silently discarding panels.

Rollback disables Universe mounting; it does not remove tasks/artifacts or rewrite saved data. Re-review source compatibility before implementation. No code or dependency changes occur while producing this plan.

## Undo and redo contract

E1.1/1 owns `panel-history.ts` and `__tests__/panel-history.test.ts`. Proposed entry:
`{scopeKey,gestureId,key,generation,before:Rect,after:Rect,source:'human'|'commander'}`.
`commitGesture(history,entry)` appends once on gesture completion (not every pointer sample), ignores unchanged rectangles and clears redo; `undoGeometry(state,history)` and `redoGeometry(state,history)` return a proposed generation-fenced geometry action and the updated history, not a direct state mutation. Bound undo+redo storage to 50 entries. Cancelled gestures create no entry; scope switch clears history.

Before applying, require the same scope/key/generation, normal visible state, and current rect equal to the recorded expected rect (after for undo, before for redo). A changed remote rect invalidates that entry and shows why it cannot be replayed; never overwrite it. Human undo may move a human-pinned panel; Commander-origin replay must still respect current pin/arrangement permission. Closed/reopened generation, minimized/maximized target or revoked source cannot be mutated. Failed/ineligible entries cannot resurrect panels, rewind ordinal counters or change content.

Each accepted undo/redo is a new E1.2 geometry operation with a new operationId and current expectedRevision. Lost ack uses receipt lookup; conflict retains the candidate without popping a successful history entry prematurely. Tests cover one long drag=one undo, redo cleared by a new drag, 51-entry eviction, no-op/cancel, pin change, close/reopen, remote-edit conflict, scope switch, receipt replay and no canonical task/action writes.
