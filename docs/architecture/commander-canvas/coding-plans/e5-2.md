## E5.2/1 — Host qualification

**Proposed files after approval:** `docs/architecture/commander-canvas/host-qualification.md` (evidence), `ui/src/components/universe/tools/IsolatedToolHost.tsx`, `server/src/services/universe-tool-host-policy.ts`, `tests/e2e/universe-tool-isolation.spec.ts`, `tests/e2e/fixtures/universe-tools/` malicious fixture bundle. Deployment header/routing file is deliberately not named as existing: BASE operator must identify actual deployment repository/route and record exact file/revision before code. No host binding is “ready” without it.

Candidate protocol to test: serve an immutable bundle at a **different registrable domain** from the application, not a sibling that inherits app parent-domain cookies. Tool origin must not share authentication cookies/service-worker scope/local storage with app. App authenticates bundle selection through its own API and issues a short-lived one-use bootstrap identity. The bootstrap is not an API token and must never be a credential for canonical APIs. Tool URLs do not contain long-lived signed storage URLs or bearer secrets. Use `referrerPolicy="no-referrer"` and explicit iframe `allow` denial for microphone, camera, geolocation, clipboard and other unused features. Baseline sandbox token is `allow-scripts` only; no `allow-same-origin`, forms, popups, top-navigation or downloads.

Proposed untrusted response CSP baseline (policy to qualify, not claimed deployed):

```text
default-src 'none'; script-src 'sha256-<deployment-computed-bootstrap-hash>';
style-src 'unsafe-inline'; img-src data: blob:; font-src 'none';
connect-src 'none'; media-src blob:; object-src 'none'; frame-src 'none';
worker-src 'none'; base-uri 'none'; form-action 'none';
frame-ancestors https://<qualified-app-origin>; sandbox allow-scripts
```

The `<...>` strings are explicit qualification inputs: operator supplies real HTTPS origin and build-computed SHA-256 script hashes for each immutable bundle, then captures actual browser response headers. Never ship this literal template or accept hashes from model-provided metadata. Bundle all permitted JavaScript into hashed inline code; dependencies/resources cannot be arbitrary remote imports. No `unsafe-eval`. Parent CSP must restrict frame-src to the qualified host. Add `X-Content-Type-Options:nosniff`, `Cache-Control:no-store` for bootstrap material and `Referrer-Policy:no-referrer`. Tool content itself may be immutable-cacheable only if its delivery/access and revocation policy permits; access cannot rely on unguessable URL alone.

**Qualification input packet:** app/tool HTTPS domains, actual reverse proxy/header files, auth-cookie flags/domain, browser/OS versions, iframe sandbox/permissions, immutable bundle hash, bootstrap issuance/consume rules, CPU/memory isolation boundary and kill mechanism, network policy, permitted asset loading path, redacted principal/org/company identity setup. Test Chromium/Firefox/WebKit desktop plus Chromium Windows if supported; record unsupported browser capability visibly rather than claim parity.

| Probe | Method and required evidence | Failure disposition |
|---|---|---|
| Origin/cookie isolation | Hostile frame reads `document.cookie`, app storage, parent DOM, app service worker; requests authenticated API with credentials; inspect network/browser console | No app token/cookie/data; any success blocks HOST |
| Network/exfiltration | Try fetch/XHR/WebSocket/beacon, image/font/media/CSS URL, DNS-prefetch, form, popup, nested frame, document navigation, dynamic import and WebRTC toward controlled canary; collect gateway and canary logs | No unintended egress. CSP does not universally prevent navigation/WebRTC; any uncovered path requires real network/process isolation and requalification |
| Navigation/download/devices | Click/mutate location, target top, `window.open`, download anchor, permissions request, clipboard; verify actual browser behavior | Denied; allowed host-mediated operations must use explicit reviewed grant |
| Bootstrap forgery | Sibling frame posts null-origin message; wrong source, instance, generation, nonce and stale frame reuse | No port/grant/data supplied; actual source-window identity is required |
| Reload/replacement | Navigate/reload frame while port action pending; restore old port | Old generation rejected before canonical dispatch; uncertain prior action uses read-only outcome |
| CPU/memory/resource abuse | Infinite loop, recursive allocation, huge DOM/canvas, message flood, repeated media decode, timers; independently measure parent input and kill latency | App usable, isolated renderer terminates at bounded limit. If ordinary iframe cannot provide the required guarantee, mark HOST blocked and design/qualify stronger containment before enabling arbitrary JS |
| Revocation | Remove company/capability access with live frame and inflight read/write | Stop new data/actions immediately server-side; invalidate generation and clear parent cache; already delivered bytes cannot be recalled |
| Teardown | 100 open/minimize/restore/close cycles and 60-minute mixed workload | Ports/listeners/network/subscriptions cleaned up, pending canonical jobs retained, measured memory within qualified budget |

- [ ] Build the malicious fixture set and expected result manifest before host component. Use a controllable local canary in test network; no requests to arbitrary third parties. Include a fake AoA approval form inside tool content; clicking it must never approve a real request.
- [ ] Run probes against actual deployment headers, not mocked iframe props. Save HAR/CSP violations, server/canary traces and OS process measurements with tool hash/browser build. Failure of process containment must stay visible; removing an iframe is not proof of reliable CPU preemption.
- [ ] Close deployment gap by recording exact host path/bundle serving service and allowed origin. Reject any path that serves arbitrary uploaded HTML on the authenticated application origin. Resolve browser opaque-origin asset loading: hashed inline bundle with data/blob resources must work under the actual CSP, not require adding `allow-same-origin` silently.
- [ ] Only after all mandatory probes pass implement `IsolatedToolHost` with qualified policy version. Store host policy version on each grant and reject stale/degraded policy. ## E5.2/2 — Capability bridge

**Create after HOST closes:** `packages/shared/src/validators/universe-tool-bridge.ts`, `ui/src/components/universe/tools/tool-channel.ts`, `server/src/services/universe-tool-capabilities.ts`, `server/src/routes/universe-tool-capabilities.ts`, `ui/src/api/universe-tool-capabilities.ts`, `server/src/__tests__/universe-tool-capabilities.test.ts`, `ui/src/components/universe/tools/__tests__/tool-channel.test.ts`. Export shared validators, mount authenticated grant routes in `server/src/app.ts`. No endpoint accepts raw SQL, arbitrary URL, generic execution or raw secret requests.

Grant is server-derived scope: authenticated user+company+conversation, immutable tool artifact/version/hash, panel instance, generation, policy version, allowed source references and named operations, issue/expiry/revocation. New proposed `universe_tool_grants` table in `packages/db/src/schema/universe_tool_grants.ts`: UUID id, organization/company IDs, actorKey, conversationId, toolArtifactId/toolVersionId, instanceId, generation integer, policyVersion, capability JSON, bootstrapNonceHash, consumedAt, expiresAt, revokedAt; server-derived organization routing metadata with explicit company/user/conversation integrity and unique active `(company,actor,instance,generation)`. Grant table is revocable metadata, not another job ledger. Token never leaves host as canonical API authorization.

**BASE security architecture gate, before grant/action-link coding:** The [worker-publication addendum](../worker-publication-plan.md) recommends application-scoped grants/action links: authenticated company/user/conversation/tool/instance predicates, not a new organization-owned job ledger. This is a proposal awaiting security review, not a worker permission extension. Implement through universe-tool-capabilities application services; remove the earlier conditional tenant repository extension for these two tables. Organization metadata is server-derived routing/integrity only. Generated schema/migration order, exact application role, parent-scoped links, same-organization/different-company, same-company/different-user, revocation and pool-reuse real-PG tests remain mandatory. Workers/frame content receive no DB access. Distributed canonical actions continue through their existing sanctioned admission boundary. No frozen set/grant expansion, owner fallback or legacy RLS retrofit. E1 state/checkpoint ownership is unchanged; HOST qualification remains independently required.

Proposed bridge protocol, distinct from canonical request schema:

```ts
export type ToolOperation =
  | { kind: "checkpoint"; state: Record<string, string | number | boolean | null> }
  | { kind: "context"; selectedReferenceIds: string[]; summary: string }
  | { kind: "read_reference"; grantedReferenceId: string }
  | { kind: "request_action"; action: "commander.request"; instruction: string }
  | { kind: "request_download"; grantedReferenceId: string };
export interface ToolEnvelope {
  protocolVersion: 1; instanceId: string; generation: number;
  requestId: string; sequence: number; stateRevision: number;
  operation: ToolOperation;
}
export interface ToolReply {
  protocolVersion: 1; instanceId: string; generation: number; requestId: string;
  state: "ok" | "denied" | "conflict" | "pending" | "unknown" | "failed";
  clientSubmissionId?: string; revision?: number;
  message?: string;
}
```

Schema is strict Zod discriminated unions: UUID instance/request/granted-reference IDs; positive safe integer generation/sequence and nonnegative safe integer stateRevision (zero before first checkpoint); instruction ≤2,000 chars, summary ≤2,000, references ≤20, checkpoint JSON ≤32 KiB, envelope ≤64 KiB UTF-8. Server-issued grantedReferenceId maps to a canonical E2.1 reference; frame cannot choose company, actor, target path or authorization. `read_reference` returns an allowlisted field projection ≤16 KiB, not entire record/secrets. External navigation and attachment picking are not included in initial allowlist; future additions need operation-specific schema, user gesture handling and qualified containment. Download request is host-mediated and reauthorizes the source using canonical content endpoint.

- [ ] Implement host bootstrap handshake: parent loads approved bundle; frame sends `ready` with fresh bootstrap nonce. Parent validates `event.source === iframe.contentWindow`, expected generation and nonce; exact origin check for non-opaque origin and source+nonce for sandbox `null` origin. Parent transfers one MessagePort to this exact window; when target origin must be `*` for opaque origin, bootstrap contains no domain data or credential. Consume nonce once with server grant. Subsequent authority flows only through that bound port.
- [ ] Validate size/schema/rate/sequence before operation dispatch. Cache reply by `(grant,requestId)` plus operation hash; identical retransmission returns same reply, changed body conflicts. Sequence replay without matching request fails. A new generation closes old ports immediately, aborts reads, revokes grant and requires fresh nonce; do not replay actions on remount.
- [ ] Add authenticated `POST /api/companies/:companyId/universe/tool-grants` to issue a reviewed-version grant after access checks, `POST .../tool-grants/:id/consume` one-use bootstrap, `POST .../tool-grants/:id/revoke`, and `POST .../tool-grants/:id/operations` from host with envelope. Server loads live grant/access and compares bound actor/company/version/generation every time. Do not trust UI checks or require a bearer token inside iframe. Reads need source permission; actions invoke the E2.2 gateway under the initiating actor and current approvals/budget. Use its `clientSubmissionId`, not a new job/request ledger.
- [ ] For action dedup add `universe_tool_action_links` in the same new schema file: organization/company, grantId FK, frameRequestId UUID, operationHash 64-hex, clientSubmissionId ≤200, createdAt; unique `(grant_id,frame_request_id)` and unique `(company_id,client_submission_id)`. Atomically reserve the mapping before E2.2 submission; same request/body reuses identity, changed hash conflicts. This is correlation only, no duplicated outcome state. One request may outlive grant expiry. Reauthorization denial stops new action; an already accepted action is observed through E2.2 and does not become a fresh request when a frame reloads. Unknown dispatch returns `unknown`; channel receipt is not completion. Keep mapping at least as long as canonical submission recovery, so deletion cannot make a stale retry fresh.
- [ ] Bind E1.2's proposed `universe_panel_checkpoints` table/migration and GET/PATCH CAS contract keyed to owner/company/conversation/instance/artifact version, then persist tool state there outside frame. E5 validates the 32 KiB state payload; E1.2 owns identity/revision/access, and E1.3 owns pending clientSubmissionId metadata only. There is no implicit existing checkpoint API. CAS stale state returns conflict with allowed revision; no automatic merge. Tool code update creates E4.3 immutable version, revokes old grant and preserves previous-version checkpoint; migrate only through registered payload migration or offer previous tool. Parent error boundary shows retry/reopen/download without recreating canonical actions. Durable tool recovery remains blocked until this producer's migration/routes are verified.

Representative channel rejection test (proposed exported helper, all identity inputs explicit):

```ts
export function matchesToolGeneration(
  expected: { instanceId: string; generation: number },
  received: { instanceId: string; generation: number },
): boolean {
  return expected.instanceId === received.instanceId && expected.generation === received.generation;
}

it("rejects stale frame after replacement", () => {
  const id = "11111111-1111-4111-8111-111111111111";
  expect(matchesToolGeneration({ instanceId: id, generation: 2 },
    { instanceId: id, generation: 1 })).toBe(false);
});
```

This proves only the comparison. Required real Playwright test uses `seedCompany`/canonical artifact creation fixtures, actual two-origin app setup, real frame windows/ports and authenticated second identity. Send valid read → replace iframe → send from old port → assert server canonical-call count unchanged. Sibling frame spoof, same request twice, changed-body same request, revocation in flight and fake approval click must also run through real origin/CSP headers. `route.fulfill`/jsdom alone cannot close HOST.

## Limits, settings, recovery and verification

Proposed unmeasured defaults: one executable tool active/user and two visible tools/viewport after qualification; 5-minute grant, one-use 30-second bootstrap; 20 messages/second sustained, burst 40, 8 pending operations, 64 KiB envelope, 32 KiB checkpoint, 16 KiB read reply; close offending channel after 3 invalid messages, security audit once per grant with aggregated counters. No raw body/secret logging. Canonical job policy controls action concurrency and spend. Require qualified parent input p95 <100ms under malicious fixture and renderer kill acknowledgement ≤2 seconds; 256 MiB renderer budget is a proposed ceiling only if runtime can enforce it. Browser iframe alone supplies no trustworthy per-frame memory or CPU limit; inability to measure/enforce is a blocking finding.

Minimize suspends data feed/ephemeral timers through port if responsive; unresponsive host is torn down and later restored from checkpoint. Close revokes renderer grant and releases ports/object URLs/media/workers, never cancels canonical work. Offline prevents new reads/actions and shows last-success status; reconnect creates fresh generation and inspects pending E2.2 outcome before allowing action. Reload, navigation and company switch revoke old binding immediately. Host loading/error/denied/revoked states use unmistakable app-owned header/banner; frame cannot draw controls over approval chrome. Source remains downloadable where authorized after crash.

Consume E8.1 theme/density/motion through a sanitized presentation message only; no settings object, provider credentials or DOM handles. OS reduced motion always wins. Host header has keyboard-accessible “Leave tool” focus escape, labelled iframe, loading status and retry/download; frame must expose working tab order/no keyboard trap for its approved version. Unreviewed custom content lacking accessible use is not advertised as qualified. Narrow 375px/200% text preserves host controls, with scrollable tool region and shared maximize; focus returns to launch control on close. Visibility never starts mic or alters voice. No application approval can be granted by a model-provided element.

Rollback: revoke all grants for disabled policy/tool version; disable new issue/consume/operations, keep read-only canonical outcome/artifact recovery; expire/reconcile grant mappings without deleting accepted work. Additive grant/action-link schema requires the BASE-reviewed generated migration and can remain through rollback. E1.2's checkpoint migration/rollback is a separate required dependency; retain its versioned payload and do not delete it with grants. Re-enable only after host policy/build qualification repeats. Old grant generation is never restored from persistent layout.
