# E6.2 Cloud live view and takeover implementation plan

> **For agentic workers:** Use `superpowers:executing-plans` only after explicit implementation approval and the applicable common-contract or connected-cloud gates defined below. This addendum runs no cloud session or provider probe.

**Goal:** Let authorized users view, pause, take control and explicitly resume a cloud browser with truthful connection and ownership state.

**Architecture:** The server authorizes separate view/input capabilities; worker acknowledgement establishes the current controller epoch. Media may fail independently of the task/browser. Client input carries current page/frame and lifecycle revisions and is rechecked at the worker.

**Tech stack:** React/TypeScript, shared E6.0 contract and a qualified cloud transport; exact media/guest SDK methods remain blocked until E6.0/2.

**Spec:** [E6.2](../slice-plans/e6-2.md), [E6.0](e6-0.md), [E6.1](e6-1.md), [integration §2](../integration-contracts.md), [UI U04/U05](../ui-review-decisions.md), [settings](../settings-contract.md), [motion](../motion-and-interaction.md).

## E6.2/1 — Authenticated live view

**Consumes:** Authorized E6.1 descriptor; E6.0/2 qualified transport with view capability, expiry and capture exclusions; E8.1 effective view-quality preference. **Produces:** A browser panel with negotiated stream state, truthful task/account/location/controller header and safe teardown. Proposed view state is `"idle" | "authorizing" | "connecting" | "live" | "stale" | "denied" | "ended" | "error"`; it is independent of descriptor lifecycle.

- [ ] **1. Bind the qualified media port.** Copy exact view-admission request/response, token scope, endpoint authentication, expiration/revocation and stream teardown from E6.0/2's accepted evidence into the new service. Register route through the existing company/actor authorization stack. Reauthorize every attach, refresh and reconnect before returning any metadata/frame. If the approved guest cannot expose headed browser-only view with required controls, stop binding; do not substitute a screenshot polling demo.
- [ ] **2. Build the actual access matrix.** In the real tenant fixture create A1 allowed view/control, A2 view-only and B1 other company; two tasks/sessions and one ended session. A1/A2 may view only their authorized task, B1 and guessed session IDs get non-disclosing refusal and zero frames. Expired/revoked token and token for the other session cannot attach. View-only never obtains input. Instrument first-frame delivery to show rejection occurs before content, not merely after a UI warning.
- [ ] **3. Implement panel subscription and cleanup.** Select the canonical session by stable panel reference, fetch current descriptor, authorize view, connect stream and display live only after its acknowledgement. On hide/minimize/close release renderer and view resources according to host policy, with no task stop/resume. Reopen reads current state; cached image is labelled stale until a new authorized frame. Ended session remains ended, preserving links to results; replacement needs distinct session identity.
- [ ] **4. Connect settings and supported controls.** Auto/reduced/high requests are bounded by the transport and policy; display actual negotiated resolution/quality after acknowledgement. Preserve old effective quality if renegotiation fails and explain it. Disable unsupported clipboard/audio/native-dialog/tab controls according to the capability record; do not claim whole-browser control from tab-only capture. Header names real task/account (or signed-out), cloud location and controller. Account label itself must be authorized metadata.
- [ ] **5. Execute UI and live-stream protocol.** Open through actual task/Universe paths, minimize/restore/maximize and resize; prove one panel/session subscription and intact task. Test black/no-frame/loading, denied, expiry, revoked access midstream, offline and server restart. At 320 CSS px, 200% text zoom and keyboard-only use, header/control actions remain reachable and content scroll/input do not drag or zoom canvas. OS reduced motion uses immediate state changes. Run a ten-minute real stream with ten close/reopen cycles; inspect media resource/lease cleanup and frame delivery counters.

**Input mapping prerequisite:** Capture dimensions come from acknowledged transport metadata, not CSS panel size. Convert client pointer position after subtracting viewport origin and letterboxing, dividing by displayed-to-capture scale; reject outside content bounds. Browser/native zoom and host canvas zoom must be included via actual DOM geometry. Test four corners, center, letterboxed margins, device scale 1/2 and host zoom 0.5/1/2 against the fixture's logged target coordinates; no clamping an outside click onto a destructive edge control.

## E6.2/2 — Takeover and reconnect

**Consumes:** E6.0 `BrowserInputEnvelope`, E6.1 canonical command/decision owner and qualified stream. **Produces:** Pure client gate plus actual worker-enforced control protocol. The following proposed pure interface is deliberately insufficient alone to authorize remote input:

```ts
export type BrowserControlState = {
  streamLive: boolean; requestedEpoch: number | null;
  acknowledgedEpoch: number | null; controllerId: string | null;
  viewerId: string; pageRevision: string | null; frameRevision: string | null;
};
export function canSendBrowserInput(state: BrowserControlState): boolean {
  return state.streamLive && state.requestedEpoch !== null &&
    state.requestedEpoch === state.acknowledgedEpoch &&
    state.controllerId === state.viewerId && state.pageRevision !== null &&
    state.frameRevision !== null;
}
```

- [ ] **1. Write the regression before wiring input.** Place in the proposed unit file; the worker suite must separately assert the same authority at execution:

```ts
import { expect, it } from "vitest";
import { canSendBrowserInput, type BrowserControlState } from "./browser-control-state";
it("waits for the new epoch and disables input on stream loss", () => {
  const pending: BrowserControlState = {
    streamLive: true, requestedEpoch: 4, acknowledgedEpoch: 3,
    controllerId: "u1", viewerId: "u1", pageRevision: "p2", frameRevision: "f8",
  };
  expect(canSendBrowserInput(pending)).toBe(false);
  expect(canSendBrowserInput({ ...pending, acknowledgedEpoch: 4 })).toBe(true);
  expect(canSendBrowserInput({ ...pending, acknowledgedEpoch: 4, streamLive: false })).toBe(false);
});
```

- [ ] **2. Implement acknowledged takeover.** User requests Take control; canonical service authorizes, advances controller epoch and asks worker to pause/fence agent commands. UI shows pausing until worker acknowledgement for that epoch, then enables input after fresh frame. Timeout/denial displays no control and disables input. A late acknowledgement for an earlier request is ignored. The UI cannot locally choose a valid epoch or claim ownership because an HTTP request was queued.
- [ ] **3. Fence actual commands and stale frames.** Worker validates authenticated session/owner/epoch/lifecycle/page/frame and command ID at execution. Deduplicate repeated command IDs with the canonical command owner; changed payload conflicts. Pointer/key down/up preserve ordering within that session. After loss release local pointer capture and clear held buttons/modifiers; reconnect cannot resend old input. A stale frame rejection requests fresh view, not automatic click retry.
- [ ] **4. Implement explicit Resume.** Human chooses Resume; canonical owner authorizes transition, worker invalidates human epoch and observes the current page/task before planning the next action. Old human input after resume is refused. BrowserPanel selection, silence, hidden view and media reconnect never resume automation. An in-flight external effect completed before fencing is reported with known/unknown outcome; no promise that pause retroactively undoes it.
- [ ] **5. Execute barrier-based race tests.** Queue agent click C1, request takeover, send human click H1 before acknowledgement (reject), acknowledge epoch 4, release C1 with epoch 3 (reject), send H2 with current frame (one effect), navigate to new page, replay H2/old frame (no new effect), Resume, replay epoch 4 input (reject). Drop media during H2 and verify task still active with input disabled. Reconnect with current descriptor/epoch; no old input playback. Repeat wrong-company token, view-only actor and revoked credential cases against a real cloud worker.

**Commands after tests/approval:** `pnpm exec vitest run ui/src/components/universe/browser-control-state.test.ts`; `pnpm exec playwright test --config=tests/e2e/playwright.config.ts tests/e2e/universe-cloud-browser.spec.ts`. Initial client test fails until its proposed module exists; connected tests fail until actual qualified view/input path exists. A passing gate helper cannot close worker fencing. ## Limits, recovery, rollback and review

Source session TTL remains E6.0's 900-second default/3,600 server ceiling/43,200 wire ceiling. Stream timeout does not extend it. Proposed takeover timeout ten seconds and token TTL sixty seconds require compatibility/security acceptance; record exact accepted expiry and observed latency before coding. No default stream frame-rate/bandwidth guarantee until measured. E8.1 quality preference is personal, while worker concurrency/lifetime/cloud budget are environment policy.

On stream loss mark stale and disable input immediately when detected; keep canonical task state and show reconnect/ended truthfully. Revocation detaches frames and clears sensitive cached pixels. In-flight action ambiguity uses E6.1 outcome reconciliation. Audit view attach/refusal, takeover/resume request and acknowledgement, stale input refusal and teardown with safe IDs; metrics track latency/negotiation, not keys/URLs/screenshots/keystrokes.

Rollback disables new stream/input admissions, revokes active capabilities and releases renderer media; worker task cleanup goes through its canonical owner. Preserve outputs and approval/result history. A server rollback cannot leave a client believing it still owns control: unknown protocol version disables input. Full authoritative Linux typecheck/test/build plus actual cloud matrix required; Windows UI fixture skip caveat is not cloud proof.
