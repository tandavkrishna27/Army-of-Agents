# E2.4 — Canonical task conversation panel implementation plan

**Status:** Review candidate; reported mock failure remains a required regression. **Version:** V1. **Spec:** [slice](../slice-plans/e2-4.md), U04/U06, E1.0/E1.1/E1.3. **Architecture:** share task content and existing reply authority inside one Universe frame, with no nested window controller. **Stack:** existing TaskDetail/WorkspaceTimeline, React Query and issues API.

## Source and files

Pinned `CommanderTaskFocusPane.tsx:19` mounts TaskDetail with `initialMode="workspace"`, anchor-derived initial tab and onDismiss. `TaskDetail.tsx` imports WorkspaceTimeline and IssueWorkspaceCard; its existing data/loading/actions must not be duplicated into a mock-only parallel task service. `issuesApi.get`, `listComments`, `addComment` and `addCommentWithAttachments` already address canonical issue/comment APIs, with clientSubmissionId support on writes.

Create `ui/src/components/universe/TaskConversationPanel.tsx`; extract reusable content from `TaskDetail.tsx` into `ui/src/components/task-detail/TaskConversationContent.tsx` and a shared task-query/composer hook only where it avoids duplication. Modify CommanderTaskFocusPane to consume the same content boundary while preserving existing non-Universe chrome. Tests: `ui/src/components/universe/__tests__/TaskConversationPanel.test.tsx`, existing CommanderTaskFocusPane tests and `tests/e2e/universe-task-routes.spec.ts`.

```ts
export type TaskConversationContentProps={issueId:string;anchorId?:string;
  active:boolean;onOpenArtifact:(artifactId:string,versionId?:string)=>void};
export type TaskPanelProps=TaskConversationContentProps & {panelKey:string;generation:number};
```

Content has no pin/minimize/maximize/close callbacks. Those belong exclusively to E1.1 frame. TaskPanelProps keys are diagnostics/context, not DOM lookup instructions. The canonical task service remains authority for replies, approval answers and agent runs.

## E2.4/1 — Shared task content and reply composer

- [ ] First extract the existing task workspace content without changing behavior. Preserve query keys, permissions, anchor resolution, event invalidation and error states. Run existing task-focus tests in the eventual implementation before adding Universe framing; this separates extraction regressions from new window behavior.
- [ ] Render concise title/status/agent in the frame/content boundary, scrollable timeline in the middle and fixed Add/message/Send composer below. Agent/material detail controls expand locally; long messages never force an oversized window. Reuse E1.3 task-destination draft.
- [ ] Submit text through `issuesApi.addComment(issueId,body,undefined,undefined,undefined,clientSubmissionId)` unless the user explicitly selected a reopen/interrupt action. File replies use existing `addCommentWithAttachments`. Do not turn every reply into a Commander invocation or inject an interrupt flag just because an attention item opened the task.
- [ ] Freeze issueId/content/attachments at Send. On durable response clear only that sent draft snapshot; stale or revoked permission keeps a recoverable unsent draft without pretending the reply succeeded. Surface unknown outcome through the read-only recovery binding described in E1.3/E2.2.
- [ ] Task questions and approval cards invoke their existing governed answer APIs; a plain comment is not a substitute for resolving a waiting question. Opening or closing the panel never marks a task done or answers approval.

## E2.4/2 — All entry points and lifecycle regression

- [ ] Needs you, Work menu, artifact source-task link, Open panels and direct reference all call one `openTaskReference({issueId,anchorId})` adapter. It resolves content permission then constructs the same E1.1 key. Different anchors scroll the existing instance after render; they do not create duplicate panels.
- [ ] Opening a second task/artifact computes a bounded initial rect within current viewport. No task-specific absolute top-left placement, nested fixed container or stale cloned preview instance may intercept lifecycle events.
- [ ] Exercise the full user-reported sequence through every entry point: open→drag→resize eight directions→pin→human move→Commander arrangement rejection→maximize→minimize→restore→close→reopen. Assert DOM visibility, registry count/generation, rect and draft after each action.
- [ ] Add passive preview tests: preview has no duplicate IDs and no active lifecycle buttons; selecting its restore target acts on the real panel. Repeat with overlapping artwork and while the task data request is delayed/failed.

Representative component assertion uses the real content/frame composition:

```tsx
const task = screen.getByRole('region',{name:'Launch design'});
await user.click(within(task).getByRole('button',{name:'Close panel',exact:true}));
expect(screen.queryByRole('region',{name:'Launch design'})).not.toBeInTheDocument();
expect(mockIssuesRemove).not.toHaveBeenCalled();
expect(savedDraft.text).toBe('Unsent reply');
```

The implementation fixture must wire real panel reducer and task API query adapters; the remove spy guards against accidental task deletion, while savedDraft is read from the injected E1.3 draft store. A frame-only direct constructor is insufficient: E2E must launch via actual attention and source-task links.

## Validation and rollback

Run existing task-focus/task workspace tests plus the new component and route E2E. Include deleted/revoked task, late query response after company switch, double Send, long transcript, narrow viewport and keyboard-only reply. Existing manual replies are independent of CMD; new delegated execution remains gated. Rollback restores the old task content mount while preserving comments, drafts and artifacts; closing the new panel deletes no canonical record.
