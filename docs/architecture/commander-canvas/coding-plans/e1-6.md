# E1.6 — Viewport, motion and accessibility implementation plan

**Status:** Review candidate; performance targets proposed. **Version:** V1. **Spec:** [slice](../slice-plans/e1-6.md), U04–U10, [motion matrix](../motion-and-interaction.md). **Architecture:** screen-fixed chrome, transformed work canvas, one cancellable camera action owner. **Stack:** React Flow controlled viewport, ResizeObserver, CSS transforms and accessible controls.

## Files and contract

Create `ui/src/components/universe/viewport-controller.ts`, `useUniverseViewport.ts`, `motion-tokens.ts`, `universe.css`; integrate E1.1 workspace, E1.4 previews and E1.5 blob/chat. E1.1 owns measured viewport data and initializes the controlled camera from AuthorizedLayoutSnapshot.viewport through viewportFromLayout. Completed camera gestures/actions emit onViewportCommit for E1.2's revisioned viewport operation; hydration and display-only clamping never emit that save. E2.1/1 defines the bounded projection contract without requiring E1.6; E8.1 supplies motion/grid/arrangement preferences. Unit tests `__tests__/viewport-controller.test.ts` and `motion-tokens.test.ts`; E2E `tests/e2e/universe-motion.spec.ts`.

```ts
export type ScreenRect={left:number;top:number;width:number;height:number};
export type Camera={x:number;y:number;zoom:number};
export function visibleWorld(r:ScreenRect,c:Camera) {
  if(![r.left,r.top,r.width,r.height,c.x,c.y,c.zoom].every(Number.isFinite)||
    r.width<=0||r.height<=0||c.zoom<=0) return null;
  return {x:(r.left-c.x)/c.zoom,y:(r.top-c.y)/c.zoom,width:r.width/c.zoom,height:r.height/c.zoom};
}
export type NavigationIntent={id:string;panelKey:string;generation:number;
  cause:'user-reference'|'commander-reference'|'background';highlight:boolean};
```

Intent is presentation metadata, never a domain permission. Revalidate referenced content and generation before moving the view. Background updates cannot pan. User/Commander requested reference moves smoothly to readable scale, then emits the transient glow; defer while typing/dragging and retain a pending target indicator. User pointer/keyboard navigation cancels the current animation immediately.

## E1.6/1 — Viewport context and placement

- [ ] Measure usable content bounds excluding tray/chat/attention hit regions; a zero-sized hidden host defers projection rather than producing NaN. Update E1.1's measured viewport snapshot (finite usable dimensions and camera); E2.1's independent builder projects that snapshot with selected/visible authorized references. E1.6 consumes the already-defined E2.1 contract for navigation integration, never owns its prerequisite data producer. Do not include unpermitted content or screen pixels.
- [ ] Use `visibleWorld` exactly once to convert screen to canvas units. New panel defaults are content-specific and capped to usable screen size; a second panel may overlap deliberately but cannot trigger fit-all or move the first panel. Preferred saved dimensions survive a smaller viewport.
- [ ] Proposed first defaults in CSS pixels: task/chat 640×520, artifact/document 760×560, browser 900×620; clamp each to usable viewport. Minimums task 320×240, artifact 320×240, browser 360×280, also capped on narrow displays. Record these as qualification candidates, not fixed product guarantees. Keep text readable through internal reflow/scroll, never scale the entire DOM composer.

## E1.6/2 — Camera, reference glow and panel transitions

- [ ] Centralize `requestNavigation(intent)` in `useUniverseViewport`. Resolve current normal/display geometry, reject stale generation, and choose a readable camera within the controller's zoom bounds. Pin protects layout arrangement; it does not prevent deliberately navigating to a pinned panel.
- [ ] Motion candidates: popup 120–180 ms, minimize/restore 180–240 ms, camera 240–360 ms, reference glow bloom/pulse/fade 1.6–2.2 seconds. Bind cancellation and duration to motion preference; direct dragging has no easing lag. Reduced motion uses immediate state changes and a brief steady indication rather than pulse/zoom travel.
- [ ] Animate a noninteractive visual proxy toward the Open panels icon for minimize; commit hidden state immediately. Do not clone focusable controls or defer lifecycle mutation to animationend. Restore shows the retained renderer at saved geometry, then animates appearance. Close only removes the target.
- [ ] Selection styling stays a quiet header tint. Reference glow uses an overlay with pointer-events:none and cannot obscure content or change selected submission targets. Start glow after requested navigation resolves, not while target is still offscreen.

## E1.6/3 — Keyboard, touch and motion qualification

- [ ] Provide focused-header move/resize shortcuts described in E1.1, visible focus rings and labelled maximize/pin/minimize/close. Preserve browser zoom shortcuts and text-selection behavior. Touch preview and resize actions have equivalent controls; hover is never the only path.
- [ ] Resize blob through edge affordances with min/max display diameter clamped to viewport; proposed 96–360 CSS px with independent 32 px control hit areas. Human/authorized Commander size changes are undoable and honor manual placement. No permanent resize symbol/background box.
- [ ] Measure at 1/10/50 panels with static text, image and live browser representatives. Record device, viewport, average/p95 input-to-paint and memory. Target p95 gesture response below 50 ms on the recorded reference device and avoid >100 ms long tasks during tray interaction; these are acceptance targets awaiting measurement, not published SLAs. Suspend hidden heavy renderers only through explicit checkpoint/resume contracts.
