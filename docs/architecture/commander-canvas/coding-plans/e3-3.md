## E3.3/1 — Gemini conformance

**Files:** Create `server/src/services/voice/gemini.ts` and future `docs/architecture/commander-canvas/voice-gemini-qualification.md`; tests in `voice-provider-conformance.test.ts`. Modify only the common adapter registry and E8.1 provider capability registration after qualification. **Consumes:** E3.1 common contract, approved credential purpose, E3.2 generation/interruption rules and E2 canonical outcome. **Produces:** A Gemini-specific adapter operation map plus declared capability record. Exact connect/session/token SDK methods remain blocked pending qualification.

- [ ] **1. Freeze official inputs.** At qualification time read Gemini Live API setup, tools, session management, ephemeral authentication, audio/transcripts, pricing and data policy docs. Record chosen model, account entitlement and region. Explicitly compare that model's tool-call blocking behavior; do not carry a capability from a different Live model or preview version. Verify whether a browser-safe credential exists for the selected transport and whether resumption authorizes a new connection or merely restores context.
- [ ] **2. Prove a harmless minimal session through the approved credential boundary.** Use company A/user A1/conversation c1; grant mic only after Start, exchange one spoken question/answer, End and inspect media/session usage termination. Seed company B and repeat access using A's connection reference: expect refusal before provider issuance. Revoked/expired keys, budget stop and unsupported model must fail clearly with typing still available. Opening Providers makes no Live call.
- [ ] **3. Qualify long-running work before implementing tools.** Submit a harmless test instruction whose canonical result is intentionally delayed thirty seconds. Observe whether the model can continue listening while a tool is pending. If the model blocks, evaluate an immediate *accepted* result containing canonical correlation followed by separately delivered confirmed result using documented supported operations. Test double delivery and dropped acknowledgement. No supported delayed-result operation means blocked integration for that model, not “completed” speech or a hidden alternate LLM. Record exact request/result event fixtures and ordering.
- [ ] **4. Implement only the qualified mapping.** Consume E3.1 `VoiceTranscript` and E3.2 generation fences; keep Gemini resume handles out of layout/history. Finalized utterance/tool handoff uses one E2.2 submission ID, and any context correction after admission becomes a new linked request. Provider resumption rechecks AoA authorization and canonical pending outcomes. Apply voice/language/model preference changes at the qualified safe turn/session boundary; rejection leaves old selection visibly active rather than silently substituting OpenAI.
- [ ] **5. Run the Gemini-specific acceptance grid.** Ten trials each: interruption during answer, session limit expiry, network loss before/after submission acknowledgement, revoked connection mid-session, conversation switch during delayed result and duplicate tool callback. Twenty utterances each in English, Hindi-English and a third supported language. Record transcript accuracy with human annotation, p50/p95 turn and local-stop latency, billed duration/usage, ended-media proof and canonical task counts. Expected: no stale audio, no duplicate task, no cross-company disclosure and every success linked to confirmed outcome. Fail capability rows individually; no vendor-parity claim.

**Failure/recovery:** Stop local audio immediately on interruption even if server truncation is delayed; disclose whether unplayed audio remains in provider context. Token/session expiry closes admission to old generation; offer explicit reconnect after outcome check. Provider transport resumption cannot replay tools. Unsupported language/voice selection returns validation feedback. Access revocation clears cached transcript view and ends session while authorized task history remains server-owned.

## E3.3/2 — ElevenLabs conformance

**Files:** Create `server/src/services/voice/elevenlabs.ts` and future `docs/architecture/commander-canvas/voice-elevenlabs-qualification.md`; extend the same conformance test file with independent ElevenLabs fixtures. **Consumes:** E3.1/E3.2 interfaces, approved connection purpose and canonical Commander service. **Produces:** An ElevenLabs/ElevenAgents operation map, declared capabilities and evidence. “Managed conversational platform” is not assumed identical to a native realtime audio model or standalone TTS API.

- [ ] **1. Freeze the exact platform boundary.** Read current official ElevenAgents authentication, conversation initiation, client/server tools, custom LLM, interrupt, transcript, retention and billing docs. Select either documented governed-tool delegation or a reviewed compatible Commander custom-model bridge based on actual evidence; record why the other is unnecessary. A generic OpenAI-compatible label does not prove compatibility with AoA's POST SSE/permissions/durable turn contract. Do not expose an unauthenticated Commander endpoint to make the custom model work.
- [ ] **2. Resolve credential/agent ownership and retention.** Document which provider-side agent configuration belongs to company A, how access is restricted, whether temporary session credentials bind that agent, permitted tools and user, and how provider recording is disabled/disclosed independently of AoA recording. Verify webhook/callback authentication and replay protection if the selected integration uses callbacks. Record deletion/retention and active-session revocation observations. If a required callback cannot be company/user scoped, stop qualification rather than trusting a session ID alone.
- [ ] **3. Prove canonical handoff under adversarial platform behavior.** Use c1 to issue one harmless task with thirty-second delayed result; return confirmed progress separately from completion only through documented supported operations. Replay a provider tool/callback twice, forge wrong conversation/company, reorder final transcript and tool delivery, and retry after the platform times out. Expect one E2.2 admitted request, immutable payload, attributable result and zero external task mutation by the platform. A changed request using the same identity is conflict, not silent original-payload replay.
- [ ] **4. Implement the qualified adapter and UI capability registration.** Translate only supported final/transcript/interruption/usage messages; preserve ElevenLabs model/voice provenance even if its internal architecture uses separate recognizer/model/synthesizer. Apply caption and speaker-silence controls without deleting transcript. No fallback to OpenAI/Gemini or different voice on a failed selection. Unsupported combinations remain explicitly unavailable, not enabled controls.
- [ ] **5. Run independent lifecycle trials.** Repeat ten interruption/expiry/revocation/loss/conversation-switch cases and twenty utterances per three languages using this provider's real connection. Test raw-audio recording off by default and opt-in only after explicit choice; verify provider-side policy separately. End while speaking and during tool wait; microphone/playback stop, canonical work continues unless separately cancelled. Record observed subscription/session usage rather than inferring zero cost from mute. Capture sanitized protocol fixtures for the automated contract suite and actual cleanup proof.

**Failure/recovery:** Reject unsigned/expired/replayed callback before reading conversation data; validate its bound scope before invoking any canonical service. Old generation callbacks may update only the original authorized canonical request; they cannot emit speech in another session. Timeout yields unknown until outcome lookup, never an automatic new tool request. If the platform cannot meet the accepted delayed-result or revocation boundary, provider remains blocked while its exact gap is reviewed.

## Automated conformance and connected evidence

For each provider record, add a case table with real redacted wire fixtures for: connect acknowledgement, partial→final, duplicate final, interrupted old audio, unknown event, expiry, revoked credential, usage and delayed result. Pure mapping tests cannot prove network authentication, capture permission, billing or data retention.

Final provider acceptance needs the actual matrix through UI and real Commander routes. Use Linux for authoritative typecheck/tests/build; Windows skip caveats from [E3.2](e3-2.md) apply. No commands or paid checks ran here.

**Numerical policy:** Do not invent session/token/audio-format maxima; take exact lower bound of documented provider and approved app policy. Reuse existing Commander 10,000/5,000/200/five input limits. Proposed test samples and thirty-second delayed result are test parameters, not provider claims. Record measured limits, default model/voice and budget handling before enabling each adapter. Keep all three V1 providers; an OpenAI pass is not sufficient release evidence.

**Observability/rollback:** Emit provider/model/connection reference/session/generation/outcome IDs, sanitized reason codes, latency and source of usage estimates. No token/audio in logs.
