# E6.1 Governed browser session ownership implementation plan

> **For agentic workers:** Use `superpowers:executing-plans` after explicit implementation approval and closed runtime bindings. No code, worker, provider or branch action is authorized by this document.

**Goal:** Associate each browser task with its admitted worker/session and preserve canonical approvals and uncertain outcomes.

**Architecture:** Universe projects the canonical execution owner's state. The worker alone executes browser commands under its live lease, controller epoch and scoped approvals. Panel selection, saved profile identity and visibility are presentation/account references, never shared live control.

**Tech stack:** Existing tenant repositories, worker protocol, browser runtime, TypeScript/React; no new scheduler or standalone browser execution queue.

**Spec:** [E6.1](../slice-plans/e6-1.md), [E6.0 contract and qualification](e6-0.md), [integration §2](../integration-contracts.md), [request contract](../request-contract.md), [settings](../settings-contract.md).

## E6.1/1 — Admitted session ownership

**Consumes:** Canonical task authorization/admission, job/attempt/worker identity and E6.0 qualified automation port. **Produces:** `BrowserSessionDescriptor` from E6.0 with actual task/account/placement/controller/capabilities. Proposed application projection `readBrowserSession(companyId: string, actorId: string, browserSessionId: string): Promise<BrowserSessionDescriptor | null>` is read-only; actual authenticated actor is server-derived. No descriptor value grants an execution capability.

- [ ] **1. Bind source-to-runtime relationships.** Trace the exact approved route/service from a user's authorized task request to admitted job, active attempt/lease, browser process and observable session. Record ID classes, foreign-key relations, source kind, actor/role checks and revocation owner. Verify where admission rejects unsupported browser targets and where legacy execution is suppressed. If task_run-only routing cannot represent the request, file/retain the specific upstream blocker; do not cast it to another source kind.
- [ ] **2. Write the negative admission fixture.** Reuse real tenant construction from upstream job-submission integration tests after reading its then-current setup, plus the frozen browser workload from `browser-job-config.test.ts`. Seed company A tasks T1/T2 and company B task T3, separate authorized/unauthorized members and worker bindings. An unauthorized request must refuse before normalization/provider lookup/launch; a malformed request from an authorized actor returns schema error. Add budget hard stop, paused target, unavailable worker and stale lease cases: zero browser launch each. This fully specified protocol cannot be reduced to a mock auth function returning true.
- [ ] **3. Implement projection after admission.** Create/recover one default live browser session per task and admitted execution attempt, with owned tabs inside that session. Two concurrent requests with the same canonical identity return the same session or explicit pending status; changed execution payload conflicts using canonical job submission semantics. Distinct tasks cannot share controller state even when they intentionally reference the same saved account. Source process restart gets a new session unless the owner proves actual continuation.
- [ ] **4. Wire display without authority side effects.** Read the descriptor and show task, account label or signed-out, local/cloud location, active controller and status. Opening/restoring/selecting a BrowserPanel only reads/attaches permitted view; it never submits a new task, obtains control or resumes automation. Unknown worker capability displays unavailable with reason. E8.1 view-quality preference affects stream negotiation only, never execution budget/lifetime.
- [ ] **5. Verify concurrency and scope through actual routes.** Race two starts for T1, then launch T2; expect one T1 session, one T2 session, disjoint controller epochs and explicit canonical attempt links. Change selected panel rapidly, minimize/close/reopen and inspect unchanged session/task IDs. Attempt cross-company reads and stolen session ID; canonical non-disclosing denial precedes metadata/frames. Revoke task access while panel open; detach its view/control without changing another task. Record DB IDs, worker launch count and UI instance identity together.

**Failure/recovery:** Starting stays pending until authority acknowledges; lost acknowledgement triggers read-only reconciliation, not a new submission. An ended session has an explicit ended state; “Start new” is separate admitted work. A source task deleted/denied produces safe inaccessible state and closes attachment. No renderer cleanup calls task cancel.

## Limits, observability and rollback

One live session per task/attempt is the proposed default, not a measured capacity guarantee; worker concurrency stays canonical policy. Do not extend source 900/3,600/43,200-second TTL bounds through panel activity. Proposed view/read request timeout ten seconds displays stale/unavailable without altering task state. Execution and approval timeout/retry policy belongs to upstream owners and must be bound before runtime coding. Preserve immutable artifacts and UI Task/API issues naming; schema additions require Drizzle generation and synchronized tenant contracts.

Audit admitted/refused session association, approval reference/status, controller change and effect outcome with company/task/job/attempt/worker/session/epoch/command IDs; no typed input, secret URLs, cookies or screenshots. An audit event is not effect confirmation. Rollback disables new browser admissions, releases view/input, and drains/cancels only through explicit canonical lifecycle operations; preserve unresolved outcomes and committed results. Never use old legacy MCP browser execution as fallback.
