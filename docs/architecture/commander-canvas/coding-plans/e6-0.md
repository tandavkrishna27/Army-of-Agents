# E6.0 Contained browser automation and streaming qualification implementation plan

> **For agentic workers:** Use `superpowers:executing-plans` only after explicit implementation approval. Qualification involving workers, installations, ports or provider sessions is future authorized work; this packet is documentation only.

**Goal:** Prove a contained Browser Use adapter and independent cloud/local view/control transports before assigning their runtime bindings.

**Architecture:** Browser automation uses the canonical admitted worker path and approval owner. Media viewing is distinct from automation, and human input requires acknowledged, worker-enforced ownership. Neither a canvas panel nor a debugging endpoint is an execution authority.

**Tech stack:** Existing TypeScript browser runtime/worker protocol, Playwright fixtures and real worker environments. Browser Use version and media transport are qualification outputs; no SDK/port/guest image is selected here.

**Spec:** [E6.0](../slice-plans/e6-0.md), [browser preparation](../implementation-plans/e6-browser.md), [integration §2](../integration-contracts.md), [engineering gates](../engineering-gates.md), [settings](../settings-contract.md), [UI](../ui-review-decisions.md).

## Proposed common E6 contract

Create after approved qualification `packages/shared/src/types/universe-browser.ts` and matching `validators/universe-browser.ts`; export through shared index. These are application-level proposed wire fields, not existing upstream types or permission tokens:

```ts
export type BrowserCapabilities = {
  view: boolean; pointer: boolean; keyboard: boolean; clipboard: boolean;
  upload: boolean; download: boolean; tabs: boolean; browserChrome: boolean;
  nativeDialogs: boolean; audio: boolean; reconnect: boolean;
};
export type BrowserSessionDescriptor = {
  browserSessionId: string; companyId: string; taskId: string;
  workerId: string; placement: "local" | "cloud";
  accountRef: string | null;
  lifecycle: "starting" | "active" | "paused" | "ending" | "ended" | "failed";
  lifecycleRevision: number; controllerEpoch: number;
  controller: { kind: "agent" | "human" | "none"; id: string | null };
  capabilities: BrowserCapabilities;
  expiresAt: string; // authority-issued ISO instant, not client countdown authority
};
export type BrowserInputEnvelope = {
  browserSessionId: string; controllerEpoch: number;
  commandId: string; expectedLifecycleRevision: number;
  pageRevision: string; frameRevision: string;
  input: { kind: "pointer"; x: number; y: number; action: "move" | "down" | "up" }
    | { kind: "key"; key: string; action: "down" | "up" };
};
```

The worker validates envelope identity/revisions/owner at execution, after enqueue as well as before. Input coordinates use the negotiated captured surface pixel space; E6.2 specifies letterbox/scale conversion tests. A descriptor does not carry relay tokens, cookies or broad worker capability. No concrete transport/session API endpoint is invented before qualification. Source mutation/audit authority is the approved upstream service; the projection cannot mint an admitted job or decision. Session lifecycle persistence must reuse upstream ownership or be designed with its reviewer before a new table is proposed.

## E6.0/1 — Contained automation adapter

**Files:** Future evidence `docs/architecture/commander-canvas/browser-qualification.md`; proposed adapter owner `packages/browser-runtime/src/browser-use-adapter.ts`; extend `packages/browser-runtime/src/__tests__/launch-guard.test.ts`, `browser-containment.browser.test.ts`, `run-session.test.ts`, and `fixture-site.ts` for a local form-effect counter. Keep existing `run-session.ts` interfaces separate until a reviewed interactive driver seam is produced.

- [ ] **1. Pin compatibility inputs.** Record exact Browser Use version/package/runtime, Playwright/browser build, local worker OS, cloud image hash and approved launch/driver API. Read current official attachment requirements. Identify whether Browser Use can accept the worker-owned pipe/browser object without a TCP debugging endpoint. If it requires CDP/remote WS, record blocked with exact API evidence; do not disable/relax the guard, expose loopback CDP in a public sandbox, or turn off Chromium sandbox.
- [ ] **2. Preserve the guard regression.** The following test uses the actual export and is a future regression addition; it proves deterministic refusal before considering any adapter:

```ts
import { expect, it } from "vitest";
import { checkBrowserLaunchSafety } from "../launch-guard.js";
it.each(["--remote-debugging-port=0", "-remote-debugging-port=9333", "/REMOTE-DEBUGGING-PORT=9222"])(
  "refuses endpoint spelling %s", (arg) => {
    const result = checkBrowserLaunchSafety({ chromiumSandbox: true, args: [arg] }, {});
    expect(result.ok).toBe(false);
  },
);
it("refuses ephemeral CDP via launch option", () => {
  expect(checkBrowserLaunchSafety({ chromiumSandbox: true, cdpPort: 0 }, {}))
    .toMatchObject({ ok: false, reason: "cdp_port_requested" });
});
```

- [ ] **3. Prove actual admission and containment.** Use two tenant companies, distinct tasks, a disposable allowed fixture origin and approved worker identity. Admit one browser job via the actual canonical route; denied actor/job must launch zero processes. Start fixture before port baseline, launch through `runBrowserSession`/approved successor, navigate/download/popup, inspect listening-port delta and teardown. Probe from an unauthorized second client only within the controlled test environment: attach/view/control all denied. Redact provider environment and tokens in evidence. Confirm the automation API drives the *same* contained browser, not a second hidden launch.
- [ ] **4. Prove action governance.** Bind exact decision producer, answer storage, delivery, worker resolver and stranded-answer recovery after APPROVAL closes. Navigate/save is denied before effect without approval; a confirmed one-shot allowance authorizes only its scoped action. Repeat answer after disconnect, expire answer, revoke actor and use wrong task/session: no accidental approval. A fixture-level resolver pass is recorded separately from an actual upstream decision-delivery pass.
- [ ] **5. Publish the adapter binding.** List exact source symbols, request/result/error types, dependencies/manifests, closure tests and supported commands. An unknown external mutation result must have durable correlation and observation-only recovery. Reject the adapter if it cannot preserve containment/authority; retain independent cloud/local protocol planning but no enabled runtime.

**Qualification command after authorization:** `pnpm --filter @armyofagents/browser-runtime test:run`; retain the package's real-browser environment requirements. Initial expected state is explicit unsupported attachment/refusal, not a fabricated import-success criterion. Existing guard tests may already pass; the new requirement is real adapter compatibility and zero alternative launch. No package/browser test ran here.

## E6.0/2 — Cloud streaming qualification

**Files:** Future `browser-qualification.md` cloud section; proposed `server/src/services/universe-browser-stream.ts`, `tests/e2e/universe-browser-qualification.spec.ts`; no guest/image/transport implementation until accepted mapping. **Consumes:** /1 admitted session, CLOUD, APPROVAL. **Produces:** Qualified cloud transport, exact media/input/auth API map and capability flags.

- [ ] **1. Name environment and disclose limits.** Record provider tier, guest OS/image, headed display/capture mechanism, browser/window selection, transport, input API, allowed network boundaries and credentials. Separate browser surface, desktop chrome, native dialogs, tabs and audio. A screenshot/video from the existing headless driver does not satisfy live view. Do not promise denied metadata reachability at the managed-shared tier; verify E8-F012 closure instead.
- [ ] **2. Run view authorization protocol.** A1 views its task/browser using short-lived session-bound view admission; A2 lacking task permission and B1 cannot receive a first frame. Revoke A1 during streaming and inspect frame/input stop; expire credentials and attempt replay for another browser/session/epoch. Verify logs, network capture and media URLs contain no long-lived secret. Record expiry and observed revocation delay.
- [ ] **3. Run ownership fencing protocol.** Queue an agent click behind a barrier. Request human takeover. Before worker pause/new-epoch acknowledgement, pointer/key input must be disabled and server/worker reject it. After acknowledgement release the old queued click: worker rejects old epoch. An already-executed click is reported, not undone or replayed. Human edits harmless fixture state; explicit Resume advances ownership and fresh page observation precedes agent action.
- [ ] **4. Run stale-frame/reconnect protocol.** Capture page A, navigate to B, replay a click with A's frame/page revision: reject and refresh. Drop media and input independently; stale image is labelled disconnected, input disabled, task lifetime unchanged. Reconnect after current authority/lifecycle lookup; destroyed/replaced browser reports ended/new identity rather than false resume. Verify second viewer cannot gain input without takeover.
- [ ] **5. Measure capability and resource matrix.** At 1280×720 and a narrow rendered panel, exercise tabs, dialogs, clipboard, upload/download and audio individually; unsupported features are false and explained. Proposed evaluation durations: ten-minute stream and ten takeover/loss cycles, recording frame latency p50/p95, throughput, CPU/memory, cleanup and actual cost. No proposed resolution/frame-rate/latency is a release performance claim. Auto/reduced/high quality must show actual negotiated quality and obey platform caps.

**Pass evidence:** Redacted admission/worker control logs, epoch timelines, fixture effect counters, media capture and actual resource teardown. CLOUD and APPROVAL closure links at the same revision are required. Unavailable headed support leaves cloud binding blocked; local qualification cannot substitute.

## E6.0/3 — Local streaming qualification

**Files:** Future qualification local section; proposed `ui/src/components/universe/LocalBrowserConnection.tsx`, `tests/e2e/universe-local-browser.spec.ts`; approved worker transport implementation path must come from producer inventory, not an invented new inbound server. **Consumes:** /1, worker auth/availability, common descriptor and approval ownership. **Produces:** Local OS capture/input capability matrix and outbound relay binding.

- [ ] **1. Bind the existing worker authentication path.** Record actual register/connect/heartbeat/revoke surfaces, certificate/token scope and expiry, reconnect identity and supported protocol version. Trace the worker-initiated outbound connection; no router configuration or public debugger endpoint. Unsupported worker versions return unavailable before session issuance. An agent API key is not automatically a remote device-control credential.
- [ ] **2. Prove browser-only capture from another authorized device.** Place visible decoy text in a separate desktop app. Start the approved worker-owned browser and view from device B as the authorized same user/company. Captured frames must contain only the selected browser surface; enumerate whether tab content, browser chrome, popups or native dialogs are captured. No screen-wide fallback when browser capture fails. Attempt unregistered device and other-company actor: no frame or input.
- [ ] **3. Repeat ownership/revision adversarial cases locally.** Pause acknowledgement before input, reject old epoch queued action, reject old page/frame coordinates, explicit Resume after fresh observation. Test browser focus loss, keyboard key-up loss, pointer capture outside panel, pinch/wheel and OS text zoom; local keyboard shortcuts must not unexpectedly control the entire desktop. Record which operations the OS/runtime can honestly support.
- [ ] **4. Disconnect and restart.** Suspend local computer, kill worker, disconnect network, close browser and restart worker separately. UI reports offline/ended truthfully and disables input immediately upon known loss. Reconnect reads worker/session/epoch; same process/session may resume only if proven live. A replacement browser has a new session ID. Cancel held buttons/modifiers on loss; never replay queued input after reconnect.
- [ ] **5. Publish local binding and teardown evidence.** Pin OS/browser/worker versions, capture permission workflow, media/auth API operations, device availability semantics and observed resource costs. Ten cycles per failure class proposed; include manual platform evidence when native controls cannot be exercised by web-only fixture. No whole-desktop capability or native-dialog/audio support inferred from tab frames.

## Verification, limits, rollback and self-review

Run future UI protocol tests with `pnpm exec playwright test --config=tests/e2e/playwright.config.ts tests/e2e/universe-browser-qualification.spec.ts tests/e2e/universe-local-browser.spec.ts`; test fixtures simulate delays/replay but actual cloud/local environments must reproduce key cases. Authoritative Linux `pnpm -r typecheck`, `pnpm test:run`, `pnpm build` precedes runtime handoff. Windows E2E embedded-Postgres skips from the existing config are not passes; report separately from real local Windows capture qualification. Current planning ran source inspection only.

Retain source TTL defaults/ceilings; task-active lifetime cannot silently extend 900 seconds or exceed 3,600 without reviewed upstream policy. Proposed relay-token TTL 60 seconds and takeover timeout 10 seconds are negotiation/review candidates, not provider-measured values; timeout disables input and leaves known canonical task state. Final limits must be recorded in the qualified producer before consumers code. Trace/video retention controls remain PROFILE-sensitive even for signed-out runs; do not conflate no cookies with no sensitive content.

Audit session admission, view attach/refusal, takeover/resume and teardown using actor/company/task/worker/session/revision/epoch and sanitized reason. Do not log screenshots, URLs with credentials, keystrokes, cookies or relay tokens. On rollback disable admissions/media, revoke input capability, drain/tear down through canonical worker owner and preserve committed outputs/audits. Do not undo an external mutation by replaying input.

Self-review covered all three increments and corrected four traps: headless recording is not streaming; legacy `browser_use` naming is not qualified Browser Use; `requireApproval` default off is not proven governance; E8-F012 requires metadata evidence as well as env absence. Remaining blocked bindings have explicit tests/inputs/owners (unassigned), not guessed APIs. E6.1–4 consume only a reviewed qualification record. All five browser slices, including saved profiles, remain V1.
