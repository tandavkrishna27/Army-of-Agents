# E3.2 Voice controls, transcript reconciliation and recovery implementation plan

> **For agentic workers:** Use `superpowers:executing-plans` only after explicit implementation approval. All checkboxes are future work; this is a documentation-only packet.

**Goal:** Keep microphone, speaker, connection, captions and Commander work independent through interruption, failure and reconnect.

**Architecture:** One session owner above renderer lifetime emits a pure state projection and explicit side effects. Provider event identity is fenced by company/user/conversation/session/generation; canonical request identity survives transport replacement. Visibility changes never become capture/cancellation commands.

## E3.2/1 — Connection and control state

**Consumes:** E3.1 `VoiceCorrelation`, qualified connect/end/interrupt/mute operations, E1.5 view lifecycle, E8.1 effective preferences. **Produces:** `VoiceState`, `reduceVoice(state,event)`, and explicit effects interpreted only by `useVoiceSession`. The code is a proposed pure interface, not existing source:

```ts
export type VoicePhase = "disconnected" | "connecting" | "listening" |
  "thinking" | "speaking" | "reconnecting" | "error";
export type VoiceState = {
  phase: VoicePhase; generation: number; micMuted: boolean;
  speakerSilenced: boolean; voiceSessionId: string | null;
  conversationId: string; errorCode: string | null;
};
export type VoiceEvent =
  | { type: "start" }
  | { type: "connected"; generation: number; voiceSessionId: string }
  | { type: "phase"; generation: number; phase: "listening" | "thinking" | "speaking" }
  | { type: "mute"; value: boolean }
  | { type: "silence"; value: boolean }
  | { type: "end" }
  | { type: "lost"; generation: number }
  | { type: "failed"; generation: number; code: string }
  | { type: "switchConversation"; conversationId: string };
export type VoiceEffect = "connect" | "closeMedia" | "stopPlayback" |
  "setInputMute" | "reconcileOutcome";
export type VoiceTransition = { state: VoiceState; effects: VoiceEffect[] };
export declare function reduceVoice(state: VoiceState, event: VoiceEvent): VoiceTransition;
```

`start` increments generation and enters connecting; `connected` is accepted only for current generation while connecting/reconnecting. `end` synchronously increments generation, clears session and enters disconnected, emitting closeMedia. `lost` invalidates playback, enters reconnecting and emits read-only reconciliation; it does not reconnect or dispatch by itself. `switchConversation` increments generation and closes media before switching destination, remaining disconnected. `failed` closes media and records safe reason. Wrong generation is a no-op. Mute changes input only; silence immediately stops playback and retains text. Neither is a work cancellation.

- [ ] **1. Write the state regression below before implementation.** It is independently executable once the named new module exists and proves the crucial independence, not full provider correctness.

```ts
import { expect, it } from "vitest";
import { reduceVoice, type VoiceState } from "./voice-state";
const active: VoiceState = {
  phase: "speaking", generation: 7, micMuted: false,
  speakerSilenced: false, voiceSessionId: "s1", conversationId: "c1", errorCode: null,
};
it("mute preserves output, end fences a late connection", () => {
  const muted = reduceVoice(active, { type: "mute", value: true });
  expect(muted.state.phase).toBe("speaking");
  expect(muted.state.speakerSilenced).toBe(false);
  expect(muted.effects).toEqual(["setInputMute"]);
  const ended = reduceVoice(muted.state, { type: "end" });
  expect(ended.state.phase).toBe("disconnected");
  expect(ended.effects).toContain("closeMedia");
  const late = reduceVoice(ended.state, { type: "connected", generation: 7, voiceSessionId: "s1" });
  expect(late).toEqual({ state: ended.state, effects: [] });
});
```

## E3.2/2 — Recovery and interruption

**Consumes:** E3.1 transcript/correlation; E2.2 stable submission and read-only outcome; E2.3 snapshot/event catch-up. **Produces:** `reconcileTranscript(expected: VoiceCorrelation, previous: VoiceTranscript | null, incoming: VoiceTranscript): VoiceTranscript | null`, plus transport-generation and utterance/submission correlation. Compare incoming company/user/conversation/session/generation with the trusted expected correlation even when previous is null. Reject lower/equal revision duplicates and wrong full scope; retain final text for that utterance. A new accepted correction after submission is a *new* canonical request referencing the earlier result, never an edit to the accepted instruction.

- [ ] **1. Add transcript adversarial tests.** Feed revisions `1 partial / 3 final / 2 partial / 3 duplicate final` for one utterance; result stays revision 3 with one finalization. Feed same utterance ID in a different conversation/session and prove it cannot overwrite. Feed two final utterances with identical text and different identities and preserve both—text equality is not deduplication. Reject negative revision, oversized text and nonfinite generation at shared validation. A restored canonical final transcript beats reconnect partial hypotheses.
- [ ] **2. Bind interruption ordering.** Stop local playback first, increment response generation, discard queued chunks, invoke the qualified provider interruption/truncation using its actual played-audio boundary, then accept the next utterance. An interrupt without transport support still stops local audio and discloses unsupported remote continuation; it must not claim the provider forgot unplayed text. Bind per-provider behavior in E3.1/E3.3. Do not call Commander task cancellation for a barge-in.
- [ ] **3. Bind reconnect recovery as observations.** Reauthenticate company/user/conversation, fetch E2.2 outcome for every pending stable submission ID, reconcile durable transcript, obtain current provider readiness, then offer explicit reconnection. Existing accepted/in-progress/completed work is displayed without re-posting. Absent is not proof of safe retry if a write may still be inflight; use the canonical owner's defined absent/unknown distinction. A provider resume token may restore audio context only after these checks. A new provider session cannot establish a new execution identity.
- [ ] **4. Run this fully specified loss protocol.** Seed A1/c1 and one submitted harmless task. Drop acknowledgement after durable admission, then end the provider transport. Count Commander user messages, task IDs and executor invocations before/after reconnect. Expect counts unchanged and recovered canonical status; outcome GET must acquire no lease and invoke no CLI. Return the old provider result after switching to c2 and verify no audio/text in c2; original result remains visible in c1. Repeat with access revoked, provider removed, server restart and missed SSE event. Each case captures canonical DB IDs plus client generation and media events, not raw secrets/audio.
- [ ] **5. Run interruption and correction protocol.** Speak a task, interrupt its spoken acknowledgement, then inspect original task status: unchanged. Explicitly request work cancellation through Commander separately and observe actual cancellation outcome. Correct an uncommitted recognition hypothesis before finalization: one request with corrected text. Correct after admission: linked second request, first payload unchanged. Duplicate final/tool callbacks cannot create a third. If canonical outcome or provider operation is missing, leave the connected case blocked rather than mark a mocked result complete.

**Test ownership and commands:** `server/src/__tests__/voice-transcript-reconciliation.test.ts` for merge semantics, `tests/e2e/universe-voice-lifecycle.spec.ts` for actual route/UI loss scenarios; run with Vitest and existing Playwright config. Assertions deliberately fail if event revision/generation guards are removed or outcome lookup calls POST. Existing mocked SSE fixture is reused for wire shape only; actual tenant/DB integration and real providers are separate qualification evidence.

**Defaults, recovery and observability:** Proposed local playback-stop target is ≤150 ms p95 over twenty interruptions; report observed timings and hardware, do not present it as measured. Blob control fade follows the existing 100–150 ms proposal and is immediate under reduced motion; neither delays End. Proposed automatic reconnect attempts remain zero until accepted provider/credential recovery; user can explicitly retry connection while typing continues. Bound retained partial transcript per utterance to the existing 10,000-character instruction limit; do not silently truncate into an executable request. Record stale-generation/duplicate drops, disconnect reason, interruption timing and canonical outcome status with correlation only. Errors are visible and sanitized; plaintext transcripts remain in authorized history, not telemetry.

**Rollback:** Disable admission, close active media through the same idempotent teardown, preserve canonical transcript/tasks/drafts and panel registry. Revert visual controls only after media shutdown. Generation counters are local runtime state; no downgrade migration can delete accepted requests. Provider-specific disconnect failure is surfaced and recorded for cleanup, not hidden as successful End.
