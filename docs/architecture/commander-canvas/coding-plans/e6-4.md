# E6.4 Browser lifetime, file transfer and saved-profile implementation plan

> **For agentic workers:** Use `superpowers:executing-plans` only after explicit implementation approval. PROFILE qualification, object-store inspection, worker sessions and schema generation are future authorized work, not actions to run from this planning packet.

**Goal:** Preserve useful task outputs across browser teardown, transfer only authorized files and support saved login reuse with measured access/revocation/retention controls.

**Architecture:** Canonical execution owns browser lifetime; canonical artifact intake/transfer owns durable files; Accounts and Access owns profile authorization. A profile is encrypted sensitive state with an independent policy and lifecycle, never a shared live session or canvas preference.

**Tech stack:** Existing worker/browser runtime, tenant repositories, artifact transfer/commit, Secrets and generated Drizzle migrations only where the producer contract needs them.

**Spec:** [E6.4](../slice-plans/e6-4.md), [E6.0](e6-0.md), [E6.1](e6-1.md), [E6.2](e6-2.md), [E6.3](e6-3.md), [artifact contract](../artifact-contract.md), [integration §2](../integration-contracts.md), [settings](../settings-contract.md).

## E6.4/1 — Task/session lifetime

**Consumes:** E6.1 canonical task/job/attempt/session and E6.2–3 media attach state. **Produces:** Read-only lifecycle projection plus explicit teardown requests through canonical execution owner. E6.0 `BrowserSessionDescriptor.lifecycle/expiresAt/lifecycleRevision` are the UI contract. Close/hide is a view event only.

- [ ] **1. Resolve duration policy without contradicting source.** Inventory upstream TTL enforcement, actual termination owner, task completion/cancel/revocation hooks and cleanup retries. Record whether task-active continuation/renewal exists and exactly how it remains within budget/worker bounds. A default 900-second browser cannot be promised to live for an arbitrarily long task. If renewal is absent, expose expiry and require a separately admitted replacement, or obtain an upstream policy/contract before claiming task-active continuity. Idle teardown is environment policy, not a personal preference.
- [ ] **2. Write lifetime separation tests.** Seed an active T1/S1 with one committed artifact, a paused T2/S2 and ended T3/S3. Close/minimize/unmount/reopen T1 panel; assert zero lifecycle mutations and S1 still active. Advance a fake canonical clock to expiry; owner schedules teardown, descriptor becomes ending/ended on acknowledgement, artifact remains readable. Revoke company/task or cancel through canonical route; session ends but unrelated T2/S2 remains unchanged. A stale lifecycle revision cannot resurrect S3.
- [ ] **3. Implement coordinated finalization.** Stop new commands and fence input; persist permitted downloads and stop trace before context close; close context; save video after flush; then release lease/resources through the existing cleanup owner. Capture failures independently so a failed output does not skip teardown. Already committed outputs never get deleted as cleanup of temporary browser data. Retry cleanup idempotently with canonical ownership/fence, not a new global sweeper that scans other tenants.
- [ ] **4. Execute real teardown protocol.** Use actual fixture `/hold` (not `/slow`, which finishes navigation) to keep browser alive. Close panel and verify process lives; then expire/cancel/revoke canonical session and measure browser/stream/lease release. Kill worker during teardown and exercise owner recovery. Download before expiry remains accessible afterward. Video save cannot wait before close; record operation ordering, process exit, active session counts and stored outputs.
- [ ] **5. Wire recoverable UI.** Show starting, active, paused, ending, ended and failed distinctly; ended panel offers results and explicit new-session action only if permitted. Offline stream never becomes “task stopped.” Narrow layout preserves status and source-task navigation. No animation delays input fencing or cleanup. Settings quality/presentation changes cannot modify expiresAt.

**Defaults/limits:** Retain source TTL bounds until a reviewed successor exists. Proposed cleanup target ≤30 seconds after owner acknowledgement is an evaluation target, not a source guarantee; measure under worker kill/network loss and record retries. No automatic browser restart after uncertain external mutation.

## E6.4/2 — File transfers

**Consumes:** Authorized selected E4 attachment refs, canonical worker transfer grants/commit, source task and session identity; E6.0 upload/download capability flags. **Produces:** Immutable canonical artifact/result references with transfer identity, hash, size, provenance and status. Proposed UI status `"selected" | "transferring" | "verifying" | "published" | "failed" | "cancelled" | "unknown"`; published requires committed canonical output, not progress 100%.

- [ ] **1. Bind the actual transfer chain.** Read `artifact-transfer-commit.integration.test.ts` setup and the current grant/commit protocol types before writing consumer tests. Map task/session/attempt/download identity to canonical artifact ID and E4 publication/version reference. Define stable retry identity per actual download; identical content from two deliberate downloads is not automatically one user operation. Document exact allowed MIME/size/path policy from E4 and worker owners. No browser filename selects an arbitrary host path.
- [ ] **2. Build the hostile download fixture.** Reuse `/download`, `/download-traversal`, `/download-absolute` from `fixture-site.ts`; exercise popup download, same-named different content and download arriving during navigation failure. Persist under resolved per-job root, grant with valid worker fence, PUT then commit verified bytes/hash, then publish through canonical E4 output owner. Inject duplicate completion/commit: one artifact publication for the same transfer identity. Changed hash under reused identity conflicts, never overwrites immutable version.
- [ ] **3. Build selected-upload authorization tests.** A1 explicitly selects attachment F1 authorized for T1; worker receives only its scoped grant. F2 from another task/company, filesystem path strings, guessed artifact ID, revoked attachment and stale lease are refused before any readable URL/bytes. No directory scan or ambient host file access. File chooser cancellation produces cancelled status and zero transfer. Browser `upload:false` disables action with supported alternative, not a pretend upload.
- [ ] **4. Implement truthful progress/recovery.** Track transfer ID and canonical outcome; retry only safe upload/commit operations according to their idempotency contract. A dropped PUT response is not necessarily absent bytes; inspect/commit through canonical owner before replay. Expired grant requires new authorized issuance for the same allowed transfer; do not resend browser form submission. Revocation blocks new grant/commit; disclose existing presign redemption window rather than claiming instant invalidation. Persist useful failed/unknown state and recoverable selected attachment reference, no token in draft.
- [ ] **5. Execute actual local/cloud file journey.** Upload F1 into harmless fixture, download resulting report, drop network mid-transfer, reconnect and inspect canonical output. Repeat revoke during PUT, job terminal before commit, size above bound, hash mismatch, duplicate callback, unsupported type and storage failure. Assert cross-tenant zero access, one immutable publication, correct source task/session and cleanup of failed temporary data through existing owner. End browser only after safe finalization attempt; committed artifact opens after session expiry.

**Test code anchor:** Extend `packages/browser-runtime/src/__tests__/run-session.test.ts`'s recordingDriver fixture with a download and trace/video; assert `saveAs(report) < close < video.saved` and `stopTracing < close`. Extend actual grant/commit integration fixtures to assert `outcome: committed` precedes UI published; do not fabricate storage APIs. These existing fixtures are file-local helpers, not imports claimed by this plan. The exact new E4 output call is bound by E4 producer before coding.

**Limits:** Source default absolute object cap 5 GiB is a backstop; E4/worker/company negotiated file cap may be lower and must appear in selection/error UI. No five-GiB browser performance promise. Presign TTL 30–300 seconds is source-owned and distinct from profile retention. Record measured transfer/resume behavior and true hash/provenance; grant audit is evidence of authorized capability issuance, not bytes delivered.

## E6.4/3 — Saved profile reuse

**Consumes:** PROFILE/E8-F011 closure, Accounts and Access current account permission, credential taxonomy, lifecycle and artifact retention owners. **Produces:** Authorized reusable profile **reference**, lifecycle/revocation/version policy and actual login restoration evidence. No cookie/storage bytes in panel geometry, ordinary attachments, voice context or generated content. This is required V1, not optional after signed-out acceptance.

- [ ] **1. Bind the profile authority and exact schema.** Request upstream record of profile owner/account/company scope, per-task use authorization, import/export policy, concurrency and version conflict rule, supported browser builds, cookie/storage encryption and key management, expiry, logout/revoke, purge and audit ownership. Source `browser_cookie_state`/`browser_storage_state` kind is not a completed saved-profile product. Determine which data may persist and which is per-job ephemeral: if retained login needs a longer-lived account store, explicitly amend/bind the retention architecture rather than override the ephemeral class through worker metadata. Account/security reviewer remains unassigned.
- [ ] **2. Inspect deployed protection inputs in a separately authorized environment.** Collect sanitized bucket encryption and lifecycle configuration with actual storage/account/prefix/versioning scope; record key/role ownership and effective expiry including old object versions. Repository grep cannot prove encryption absent/present. Verify lifecycle policy applies to sensitive object prefixes and quantify expiry lag. Derive a policy-approved profile TTL and purge deadline; do not propose an arbitrary 30-day login retention as though accepted.
- [ ] **3. Prove real sensitive-path creation/access.** Use a disposable fixture login containing unique canary cookie/storage values for company A, then save via the real approved worker/profile path. Restore in a different authorized A task with a fresh browser session; prove expected login state and no shared live controller. B1, revoked A2 and guessed profile/version cannot obtain grant or material. Inspect canonical retention decision and grant-issuance audit records on the actual sensitive kind, including agreeing/disagreeing retention declarations; no-row semantics must match the existing audit contract. Never print canary secret values in review reports.
- [ ] **4. Prove revocation, TTL and purge separately.** Revoke account access between view and profile materialization, between grant and download, and while a browser is active. Deny new reuse immediately at the authority; record any previously issued grant's remaining redemption window and active-cookie exposure. End affected active sessions according to accepted policy, wipe in-memory/on-disk browser state through its owner, and confirm logged-out/new attempt denial. Test TTL expiry and job-completion cleanup independently; the orphan sweeper excludes committed artifacts and cannot satisfy either by assertion. Inspect current versions, old versions/backups and worker disks according to the approved deletion scope, with measured purge deadline and failure retry record.
- [ ] **5. Prove audit and failure behavior.** Exercise profile save/read/reuse/revoke/expiry/purge; show attributable durable event or explicitly documented best-effort failure handling. Inject audit-write failure and confirm alert/repair path rather than pretending an audit row exists; current grant/retention writers do not fail the already successful operation. Grant issuance must not be reported as redemption; use object-store access evidence if actual download proof is required. Kill worker during profile save/purge, corrupt encrypted bytes, rotate key and simulate retention-store outage: fail closed for reuse, retain safe metadata/status, and recover without leaking another profile.
- [ ] **6. Close gate with accountable reviewers.** Attach source revision, actual provider/bucket policy, fixture-login restore, cross-tenant and revoked-access evidence, TTL/job-completion purge results, audit semantics/failure results and rollout/rollback outcome. Reconcile E8-F011's stale audit prose and remaining clauses through upstream owner; do not simply flip a Universe checkbox. Unsatisfied encryption/TTL/cleanup/real-sensitive-path evidence leaves /3 and V1 incomplete.

**Profile UI:** Saved profile name/account/current availability comes from authorized metadata; unavailable/revoked state has clear access guidance and no silent signed-out “success.” Explicit profile selection references an allowed version/account, not a cookie attachment. Simultaneous profile update policy must be defined by Accounts and Access (snapshot/version conflict or approved serialization); two tasks never merge cookie stores silently. A denied/revoked profile should not leak which other company owns it. Personal settings reset cannot remove account secrets/profiles.
