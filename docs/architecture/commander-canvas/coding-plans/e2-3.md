```ts
export type ReconciliationState={generation:number;lastSeq:number;status:'loading'|'current'|'stale'|'offline';dirtyRefs:string[]};
export type EventHint={seq?:number;referenceKey:string};
export function acceptHint(s:ReconciliationState,e:EventHint):ReconciliationState {
  if(e.seq!==undefined && e.seq<=s.lastSeq) return s;
  return {...s,lastSeq:e.seq??s.lastSeq,status:'stale',
    dirtyRefs:[...new Set([...s.dirtyRefs,e.referenceKey])]};
}
```

This helper schedules reads only, never a job. A seq-less local event cannot advance a durable cursor. Authorization-filtered sequences can contain gaps; do not interpret every numeric gap as lost delivery. Domain revisions/state reconcile duplicates and out-of-order notifications.

## E2.3/1 — Truthful catch-up

- [ ] Read user/company/conversation ownership before composing snapshot. Re-resolve only relevant bounded refs using existing task/artifact/message/hub services. A completed task is canonical status, not inferred from a notification title, animation or provider saying “done.” Include snapshot observedAt and stale/partial reasons.
- [ ] Capture durable currentSeq before snapshot reads, subscribe/buffer through existing live updates, fetch canonical snapshot, then consume/replay newer hints. This is not a transactionally consistent whole-company snapshot: idempotent refetch/revision checks handle rows observed at different moments. Never advance cursor past events that were not actually reconciled.
- [ ] Use E2.2 observation for pending submitted turns. Unknown stays unknown, and catch-up must not create a new Commander turn merely to explain status. An optional natural-language summary uses existing conversation context with authoritative facts, not independent tool authority.
- [ ] Add tests in `server/src/__tests__/universe-catchup.test.ts` for deleted/revoked items, exact-version output, late completion, unknown submission and limited reference batches. Ensure inaccessible item counts/titles do not leak through aggregate summaries.

## E2.3/2 — Disconnect, replay and canonical refresh

- [ ] Implement `useUniverseReconciliation` as a consumer of LiveUpdatesProvider. Cache by company/user/conversation and cancel old-generation reads when scope changes. On socket disconnect show stale/offline; existing content is not labelled current simply because it remains visible.
- [ ] On reconnect use the shared cursor protocol. Retention overflow or snapshot fallback triggers a new canonical snapshot, not a full historical replay or duplicate subscription. A failed durable append is recovered through bounded safety refresh of relevant state, not an assumption that no event means nothing changed.
- [ ] Proposed initial bounds: 100 changed refs per read batch, coalesced 200 ms invalidation, 30-second visible-workspace safety refresh, exponential network retry capped at 30 seconds with jitter. Suspend routine refresh in hidden tabs and refetch on visibility/network return. These are engineering defaults to measure, not SLAs or permissions to run work.
- [ ] Add `tests/e2e/universe-reconnect.spec.ts`: connect two clients, lose ack, mutate canonical task while one is offline, reconnect, force retention-floor fallback, revoke task access, return. Assert one final output, no extra POST chat, no cached forbidden preview and unchanged unsent draft. Disable durable store in a fixture and verify safe stale→canonical-refresh recovery.
