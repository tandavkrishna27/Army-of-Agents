# E3.4 Split and local speech qualification implementation plan

> **For agentic workers:** Use `superpowers:executing-plans` only after explicit implementation approval and the V2 gate below. This document permits neither model downloads nor device/provider execution.

**Goal:** Add independently selected recognition/synthesis and qualified local speech after the complete V1 is verified.

**Architecture:** Recognition produces versioned utterances; Commander owns accepted requests/results; synthesis consumes authorized confirmed text. Local audio processing is a deployment capability and never implies an offline AoA control plane or arbitrary host-process execution.

**Tech stack:** Existing TypeScript/shared types and approved desktop/worker capability surface. Recognizer, synthesizer, SDK, model and packaging remain qualification outputs.

## E3.4/1 — Split recognition and synthesis

**Consumes:** E3.1 correlation/transcripts and approved credential purpose; E3.2 transcript revision/playback generation; E2 canonical outcomes; E8.1 capability-specific connections. **Produces:** A compatibility matrix for recognizer × synthesizer × language × transport; an explicit runtime contract with normalized format, turn finalization and cancellation behavior. Candidate vendor names in the September research are candidates, not chosen dependencies.

```ts
// Proposed shared record; concrete adapter methods follow qualification.
export type SpeechMode = "realtime" | "pipeline" | "local";
export type SpeechCombination = {
  id: string;
  recognitionConnectionId: string;
  synthesisConnectionId: string;
  recognitionModel: string;
  synthesisModel: string;
  language: string;
  status: "unqualified" | "validated" | "unavailable";
  evidenceRevision: string | null;
};
```

- [ ] **1. Qualify documentary inputs and data boundaries.** For each proposed recognition/synthesis pair, record current official APIs, model/version, regions, retention, tokens/credentials, audio formats, sample rates, transcript revisions/commit semantics, cancellation and usage. Identify every audio/text transfer recipient; two vendors means two explicit data paths. No automatic fallback adds an unapproved recipient.
- [ ] **2. Specify finalization before dispatch.** A provider partial does not submit. Accepted finalization is one authoritative utterance ID/revision: once a user turn is committed, assign one canonical E2 submission ID. Correction before commitment replaces the pending hypothesis; correction after commitment creates a linked new request. Record the exact provider-specific end-of-turn signal and how long late corrections remain possible; no invented universal silence threshold.
- [ ] **3. Implement only a validated pair.** Decode input once into the qualified format, pass bounded frames to recognition, reconcile hypotheses through E3.2, route the final instruction through Commander, synthesize only confirmed authorized response text. Keep recognition generation, canonical request identity and playback generation distinct. Silence suppresses playback without discarding transcript; mic mute stops new frames without cancelling work.
- [ ] **4. Run the fixture protocol.** Input utterance U receives partial `create a task`, revision 2 correction `summarize this task`, final revision 3; inject duplicates and revision 1 after final. Expected one canonical submission with final text. Then submit a late user correction after durable acceptance; expected second linked request, first unchanged. Stop synthesis midway, deliver late chunks and verify zero playback after stop; task remains running. Run swapped provider combinations only when listed validated; unsupported combinations fail at selection before audio disclosure.
- [ ] **5. Run live pair qualification.** For each enabled pair record twenty utterances per three supported languages, twenty interruptions, ten disconnects at each recognizer/Commander/synthesizer boundary, noisy input and thirty-second delayed Commander result. Inspect canonical counts and timings, raw recording opt-in, disclosed provider retention and actual usage. Zero duplicate submissions and exact text provenance are required; record measured latency/error rates without promising parity with realtime.

**Recovery/limits:** A recognizer outage preserves recoverable unsubmitted text and offers typing; synthesis outage preserves text and does not resubmit work. Bound instruction/context/attachments by existing 10,000/5,000/five limits; audio frame and buffering limits must be measured/documented before implementation. Proposed queued audio maximum is two seconds, drop/cancel oldest invalid generation, not silently truncate the instruction. Reviewer must accept a measured buffer/latency policy before enablement. No persistent raw audio unless opt-in and retention owner are bound.

## E3.4/2 — Local speech runtime

**Consumes:** Approved desktop/worker capability and V1 identity/permissions; E3.4/1 utterance/synthesis boundaries. **Produces:** Supported OS/hardware/model packaging matrix, verified installation/update/uninstall behavior, resource limits and an authenticated local capability handle. It does not produce a new control-plane executor.

- [ ] **1. Inventory the approved host surface.** Identify the actual desktop capability API and its owner/version at execution base. Record how signed binaries/models are obtained, hashes/signatures verified, storage location selected, user consent captured and update rollback performed. If no approved surface can expose microphone/speech runtime, mark local binding blocked; do not borrow arbitrary shell/process adapters. Engine and every voice model license need packaging review; no current license claim is inferred from old research.
- [ ] **2. Build a hardware/OS qualification table.** Choose supported Windows/macOS/Linux variants only after testing; for each list CPU architecture, RAM, optional GPU/backend, model language/version/hash, installer size and disk footprint. Record cold/warm start, memory peak, sustained CPU, recognition/first-audio latency and thermal behavior. Proposed lower-spec test machine must be explicitly named; no universal “runs locally” statement without evidence.
- [ ] **3. Qualify device and permission lifecycle.** Test missing model, corrupt model/hash mismatch, denied mic, unplugged mic, unavailable output device, locked/sleeping machine, process crash, disk full and update interruption. Expected unavailable/error state is actionable, cached transcript remains recoverable, all tracks/processes are stopped on End, and no second Commander request is created. A device change resolves locally; another device never receives the original device identifier as a usable default.
- [ ] **4. Qualify network separation.** With local engines installed, capture egress in a disposable environment: audio inference must use only the approved local engine; connected Commander still needs its authorized server. Disconnect the network after recognition finalization but before admitted acknowledgement; show pending/unknown and later read canonical outcome, never assume local/offline task execution. Reconnect a different account/company and prove old frames/text are not sent there.
- [ ] **5. Implement the approved bridge and resource enforcement.** Bind exact desktop handle/methods only after the preceding record is accepted. Use generation-scoped audio frames, the common transcript reconciler and one canonical Commander bridge. Kill/restart the speech subprocess only through its owning capability; never kill an unrelated CLI. Installation rollback restores the prior verified model and invalidates active inference session; it does not erase conversation data.

**Protocol output:** Redacted device/runtime logs, binary/model provenance, resource measurements, per-case transcript/request IDs, process teardown and media-release proof. Individual local-runtime/platform reviewer remains unassigned. No hardware/latency claims are measured in this planning pass.

## E3.4/3 — V2 regression and rollout

**Consumes:** All V1 accepted results, /1 and /2 qualification, E8.1 scoped preferences and Providers catalog. **Produces:** Mode configuration and compatibility gating that preserves all V1 behavior.

- [ ] **1. Enforce the execution gate.** Attach the E8.2 release matrix showing every V1 slice qualified; missing PROFILE, CLOUD, VOICE or CMD evidence keeps V2 execution blocked. Reviewer approval of a plan is not implementation approval. Record the user's explicit V2 authorization separately.
- [ ] **2. Extend existing settings via their owner.** Add a personal speech-mode selection and recognition/synthesis selectors limited to validated combinations. Providers owns connections/readiness; Universe stores references/preferences; Budget & caps owns limits; shared Commander style remains one audited configuration. Default existing users to their current realtime mode. Unknown mode/version is unavailable with recoverable saved values, never a silent provider switch.
- [ ] **3. Specify and generate any additive migration.** E8.1 owns field-patch validation, revision conflict and section-reset behavior. Add optional fields with compatible readers; reset clears only mode overrides. Generate schema with Drizzle only if persistence needs new columns/tables, update shared/server/UI contracts and migration tests together. Do not delete realtime keys or credentials on downgrade.
- [ ] **4. Run the mode-switch sequence.** Start realtime, switch to pipeline at an explicit safe boundary, interrupt, switch conversation, end, select local, unplug device, restore realtime. For every switch close old media/generation, inspect canonical pending outcomes, preserve captions/history, and require explicit capture restart. Verify unavailable pair, failed save, revision conflict, provider revocation, reload and narrow-screen/keyboard/reduced-motion controls.
- [ ] **5. Re-run all three V1 realtime provider matrices and browser/Commander connected smoke journeys.** Disable each new mode independently: new starts refused, active media closed, completed transcripts/tasks remain. Test rollback to an old reader with new-mode preferences; retain the record disabled and readable for reset. Compare budgets/usage attribution to provider records, including local inference versus hosted Commander costs.
