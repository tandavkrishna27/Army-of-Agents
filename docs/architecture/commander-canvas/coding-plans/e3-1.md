# E3.1 OpenAI realtime qualification and integration implementation plan

> **For agentic workers:** Use `superpowers:executing-plans` only after explicit implementation approval, one checked increment at a time. This packet authorizes documentation only; do not run providers, install dependencies, change branches, or reuse the premature E1.1 worktree.

**Goal:** Connect explicit OpenAI voice sessions to the existing authorized Commander conversation, with truthful readiness and confirmed work outcomes.

**Architecture:** Speech is replaceable transport/presentation around Commander. Provider sessions do not own task execution, idempotency, approvals or conversation permission. Qualification must establish a speech-purpose credential boundary before any provider SDK binding is written.

**Tech stack:** Existing TypeScript/React, Express and repository test runners. Provider model, SDK, transport and credential issuance details are outputs of qualification, not selected dependencies.

## E3.1/1 — Provider contract qualification

**Files:** Create, during an authorized qualification phase, `docs/architecture/commander-canvas/voice-openai-qualification.md`; proposed implementation owners `packages/shared/src/types/universe-voice.ts`, `packages/shared/src/validators/universe-voice.ts`, `server/src/services/voice/openai.ts`. Modify `settings-contract.md` only to record an accepted concrete binding, not to relocate Providers or Budget & caps. Test owner: `server/src/__tests__/voice-provider-conformance.test.ts`.

**Consumes:** E8.1 company-scoped provider readiness/preferences; E2.1 immutable selected context and E2.2 canonical submission/outcome ownership. **Produces:** One provider capability record, credential decision, redacted protocol transcript and adapter-to-wire operation map. The following is an AoA-owned *proposed* contract, not an OpenAI API signature:

```ts
export type VoiceProvider = "openai" | "gemini" | "elevenlabs";
export type VoiceCapability = {
  provider: VoiceProvider;
  connectionId: string; // authorized reference, never a key
  model: string;
  transport: "webrtc" | "websocket" | "brokered";
  partialTranscripts: boolean;
  finalTranscripts: boolean;
  interrupt: boolean;
  resumeTransport: boolean;
  usage: "reported" | "estimated" | "unavailable";
  validatedLanguages: readonly string[];
};
export type VoiceScope = {
  companyId: string; userId: string; conversationId: string;
}; // server derives company/user from the authenticated request
export type VoiceCorrelation = VoiceScope & {
  voiceSessionId: string; generation: number;
};
export type VoiceTranscript = VoiceCorrelation & {
  utteranceId: string; revision: number; text: string; final: boolean;
};
```

## E3.1/2 — Session integration

**Files:** Create `server/src/services/universe-voice.ts` (session admission and identity), `server/src/services/voice/openai.ts` (qualified wire adapter), `ui/src/components/universe/useVoiceSession.ts` (device/transport owner), `server/src/__tests__/universe-voice.test.ts`. Add routes in `server/src/routes/internal-agent.ts`, shared voice exports in `packages/shared/src/index.ts`, UI API methods in `ui/src/api/internal-agent.ts`; E8.1 owns preference/provider storage. Exact credential and wire bindings depend on the accepted documentary/security outputs of /1 and E8.1/1. The live /1 verdict closes after this consumer exists; it is not a prerequisite for writing the consumer. No fictional endpoint is assigned.

**Interfaces:** Proposed server orchestration functions `startVoice(scope: VoiceScope, connectionId: string, clientStartId: string): Promise<VoiceCorrelation>` and `endVoice(scope: VoiceScope, voiceSessionId: string)` returning a typed ending/ended/unknown outcome through the shared contract are application intent boundaries only. Actual start response connection material must be typed after /1 and excluded from logs/storage. A session ID is correlation, never authorization. E2.2 remains the sole submission/outcome API producer; bind its finalized exported types before writing this consumer. Do not clone them here.

- [ ] **1. Build refusal tests at the real route boundary.** Extend the route stack patterns in `internal-agent-chat-route-sse.test.ts`, but add the real authorization middleware in the new integration fixture. Seed A1/A2/B1 and company-owned connections/conversations. A1 may start A1's permitted connection; A2/B1 attempts return the canonical denied/not-found result before provider issuance. Missing config, expired capability, hard budget stop and revoked secret call the provider zero times. Schema rejection covers empty IDs, unknown fields and unsupported voice/model pairs.
- [ ] **2. Write admission and lifecycle implementation after binding.** Resolve actor from request and authorize conversation/connection. Atomically persist the start identity, single-owner slot and canonical budget reservation before vendor admission. Only the fenced session owner may resolve the restricted credential and issue the external start after its starting transition is persisted. On post-issuance uncertainty, request closure and retain ending/unknown ownership plus budget exposure until the qualified outcome is known; never claim no session solely because acknowledgement failed. Retry the same `clientStartId` returns the same active start outcome or explicit terminal status; it cannot create two billable sessions. Enforce one nonterminal session per company/user across devices/tabs with the partial unique index and state constraint in the review corrections; this is application policy, not a provider limit.
- [ ] **3. Connect explicit controls and preferences.** Start only from user action. Load effective provider/voice/language/style and device-local mic/speaker choice at start; validate against capability record. Opening/showing blob, chat, captions, reload and preference sync never start capture. Permission denial stays disconnected with an actionable explanation. Stop/end closes tracks, playback and transport while preserving conversation/blob. E3.2 owns fine-grained state transitions.
- [ ] **4. Bridge finalized work only.** Freeze E2.1 context and stable client submission ID once per accepted utterance. Pass content through E2.2's canonical Commander owner, preserving provenance as correlation. Duplicate provider tool calls reuse the original identity and verify payload equality; changed payload conflicts. A result may be spoken only after canonical outcome observation. Source speech cannot broaden role. Keep provider conversation context within authorized data and the established context limits.
- [ ] **5. Verify ordinary and adversarial seams.** New unit/integration tests assert provider-issued material never enters serialized settings/layout/draft/activity output, logs or canonical messages; a second company sees neither readiness nor session. Test expired token during handoff, revoke after issue but before connect, callback arriving after end, duplicate start, budget denial, server restart and unknown start acknowledgement. Provider callback loss never causes a new Commander request. Re-run the real provider matrix from /1 against actual routes, not an adapter-only harness.

**Observability:** Audit explicit start/end/check/config mutation and refusal reason with company, actor, connection reference, session, generation and canonical request/result IDs. Metrics record connect latency, interruption latency, stale-event drops and reported versus estimated usage; no raw audio or transcript in metrics. Store transcript only through the authorized conversation retention owner.

**Limits/release/rollback:** Provider TTL and usage caps come from /1 plus Budget & caps, whichever is stricter. Proposed UI start deadline 15 seconds and reconnect attempts 0 automatically until outcome/credential qualification; timeout means failure/unknown, not permission to issue again. Disable new admissions on rollback, terminate connections, retain canonical messages/tasks and audit. Run full Linux `pnpm -r typecheck`, `pnpm test:run`, `pnpm build` before runtime handoff; Windows E2E limitations are detailed in E3.2. No runtime claim is made.
