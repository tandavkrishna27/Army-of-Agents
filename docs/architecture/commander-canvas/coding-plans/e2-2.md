## Contract

GET `/api/companies/:companyId/internal-agent/conversations/:conversationId/submissions/:clientSubmissionId` returns an owner-authorized observation. It must not construct `agentLoopService`, insert/update a run, claim/heartbeat/finish a turn, call CLI, or resolve an approval. Unknown ID yields an explicit unknown observation, not a retry instruction. Foreign conversation returns not-found under canonical ownership rules.

```ts
export type SubmissionOutcome={clientSubmissionId:string;observedAt:string;
  state:'unknown'|'accepted'|'running'|'succeeded'|'failed';
  userMessageId?:string;replyMessageId?:string;runId?:string;
  reason?:'not-observed'|'lease-stale'|'legacy-unlinked'|'recorded-failure'};
export type TurnObservation={userMessageId?:string;replyId?:string;runId?:string;
  turnStatus:string|null;leaseFresh:boolean};
export function classifyTurn(t:TurnObservation):SubmissionOutcome['state'] {
  if(t.replyId) return 'succeeded';
  if(!t.userMessageId) return 'unknown';
  if(t.turnStatus==='failed') return 'failed';
  if(t.turnStatus==='running') return t.leaseFresh?'running':'unknown';
  if(t.turnStatus===null) return 'accepted';
  return 'unknown';
}
```

A linked tool-only reply with empty content is still succeeded. `done` without linked reply remains unknown/inconsistent rather than borrowing a later assistant message. Lease freshness uses existing conversation lease constants; it does not prove a worker is alive or authorize a lease takeover.

Verify version membership and current actor access. Nullable/missing versionId remains unbound and blocks exact-version publication; never substitute latest version, an unrelated later message, clientSubmissionId or runId.
