## What is settled, and must not be re-litigated

| Decision | Why | Source |
|---|---|---|
| Watermark parameter is **REQUIRED, no DEFAULT** | The certificate is blind to `proargdefaults`; an optional parameter is a fail-open with a green certificate | §10.2, measured |
| The read returns **exactly one row, always**: `(lease_ids uuid[], unnarrowed_total bigint)` | A `RETURNS TABLE` of the matches returns ZERO rows when the narrowed set is empty, so the total vanishes exactly when the churn guard needs it | §11.1, measured |
| The old 2-arg signature is **DROPped** | A surviving overload does **not** raise 42725 with a required parameter — it resolves **silently to the old, unnarrowed function**. A missed call site fails OPEN | §11.2, measured |
| `identityArguments` says **`timestamp with time zone`** | The catalog renders it that way and the manifest compares exactly; `timestamptz` is a fatal every-boot failure | §11.2, measured |
| The gate compares the **marker's** generation, not each record's | A rotation after a clean pass otherwise bricks the company permanently — `onConflictDoNothing` means a re-run cannot re-tag | §12 |
| All generation comparisons use **`IS DISTINCT FROM`** semantics | `<>` misses NULLs entirely; NULL is a normal value | §13, measured |

## Task 2: The new definer read

**Files:** a new migration; `server/src/db/security-definer-manifest.ts`;
`server/src/services/canary-preflight-evidence.ts`

- [ ] **Step 1: DROP, then CREATE**

```sql
DROP FUNCTION IF EXISTS public.canary_preflight_evidence_leases(uuid, uuid);
```

★ Not hygiene. With the required third parameter, leaving the 2-arg form alive means a stale call
**silently returns the unnarrowed set** (§11.2, measured). After the DROP a stale call raises 42883,
which is loud. The DROP is what converts a silent fail-open into a visible failure.

- [ ] **Step 2: The one-row body**

```sql
CREATE OR REPLACE FUNCTION public.canary_preflight_evidence_leases(
  p_organization_id uuid, p_company_id uuid, p_watermark timestamptz)
RETURNS TABLE (lease_ids uuid[], unnarrowed_total bigint)
LANGUAGE sql
STABLE
SECURITY DEFINER
SET search_path = ''
AS $$
  -- ONE ROW, ALWAYS. array_agg over an empty narrowed set yields NULL, count() yields 0, and the
  -- row still exists -- which is the whole point: `unnarrowed_total > 0 AND lease_ids IS NULL` is
  -- the "the pass predates the entire fleet" case, and a RETURNS TABLE of the matches cannot
  -- express it (design section 11.1, measured).
  SELECT array_agg(l.id) FILTER (WHERE l.created_at <= p_watermark),
         count(*)
  FROM public.environment_leases l
  WHERE l.company_id = p_company_id
    AND EXISTS (SELECT 1 FROM public.companies c
                WHERE c.id = p_company_id AND c.organization_id = p_organization_id);
$$;
```

★ **No DEFAULT on `p_watermark`, now or ever** — §10.2. Add the same warning comment `0268` carries.
★ Verify against Task 1's probe that `array_agg … FILTER` behaves as written under `search_path = ''`.

- [ ] **Step 3: REVOKE / GRANT and per-statement C14 comments**, exactly as `0267` and `0268` do.

- [ ] **Step 4: The manifest entry**

Hash it with `node scripts/definer-body-sha256.mjs <the new migration>` — the generator 2.3 shipped.
`identityArguments` is **`p_organization_id uuid, p_company_id uuid, p_watermark timestamp with time
zone`**. Then run the startup certificate suite, which validates the hash against a real catalog.

- [ ] **Step 5: The evidence reader**

`readCanaryPreflightLeaseIds` becomes a reader of the one-row shape and returns **both** facts. Do not
let a caller project by name and drop the total — §11.4 measured that this is silent.

## Task 4 ★: The three new refusals

**Files:** `canary-preflight.ts`

Add `reconciliation_stale` to `CanaryPreflightRefusalReason`.

★ **This reds nothing.** There is no exhaustive switch on the reason anywhere — `run-execution-owner.ts:256`
just interpolates it into a string (verified). The type system will not force any site to learn about
it, and it will not catch a refusal condition you forget to write. **Pin the reason set in a test**
so the surface is enumerated somewhere.

- [ ] **Step 1: No marker, or a stale marker** → `reconciliation_stale`.

The freshness comparison happens **in SQL**, against the database clock on both sides. §11.4: doing it
against a JavaScript `Date` reintroduces the exact two-clock bug §3.3 exists to close. The bound is an
exported, documented constant — **not** an `AOA_*` environment variable (`brand-check` bans
undocumented ones in `server/src`, and a value this load-bearing should be reviewed in a diff).

- [ ] **Step 2: The churn arm** — `unnarrowed_total > 0` while the narrowed set is empty →
  `reconciliation_stale`. This is the arm that only exists because of the one-row contract.

- [ ] **Step 3 ★: The generation comparison moves to the marker (§12), with `IS DISTINCT FROM` (§13)**

Replace the per-record `superseded` filter at `:157-171` with a comparison of the **marker's**
generation to the current one. Keep `:150-156` exactly as it is — "no current generation at all" is a
different question and remains correct.

★ **Pin all four combinations**, and the second is the one every naive implementation gets wrong:

| marker | current | verdict |
|---|---|---|
| `'ungenerationed'` | NULL | not stale |
| `'ungenerationed'` | `'S2:1'` | **stale** |
| `'S1:1'` | `'S2:1'` | stale |
| `'S1:1'` | `'S1:1'` | not stale |

- [ ] **Step 4: Mutation-check the churn arm and the generation arm.** Delete each in turn and
