# MIG-010 Unit 2.3 — make the reconciliation pass actually run

> **For agentic workers:** implement task-by-task, in order. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Close **E10-F002**. MIG-008's pass and its store both have zero production callers; this
unit gives them one, and makes the pass something that *can* run — organization-scoped, **read-only**,
reading through a new owner-owned `SECURITY DEFINER` function, driven by an operator CLI that asserts
the role it connected as, and enrolled in the repo's own zero-caller register so this defect cannot
silently recur.

**Not in this unit:** the watermark, the freshness bound, `reconciliation_stale`, any change to
`canary_preflight_evidence_leases`, any gate change. Those are Unit 2.4. **The canary stays shut.**

**Design authority:** [`2026-09-01-blocker-e-2-e-3-design.md`](./2026-09-01-blocker-e-2-e-3-design.md)
— read **§10 first** (revision 4 withdrew §4.3's mechanism as a fail-open), then §1, §4.1, §9.2.

## Why the sequencing changed

An earlier split had the definer surface land alone, ahead of its caller. That would ship a
**zero-caller definer function** — the exact defect class E10-F002 *is*. A terrain sweep separately
confirmed *"nothing mechanical will notice if the new caller is removed, or was never reachable."*

So the function is born **with** its caller, in one PR. And the arity change on
`canary_preflight_evidence_leases` — where most of the confirmed HIGH hazards live (call sites a
`(uuid, uuid)` grep cannot find; the 42725 overload trap; the prefix-matched shape test) — is
deferred to 2.4, where the gate will actually have a watermark to pass.

## Task 2: The hash tool the repo never had

**Files:** Create `scripts/definer-body-sha256.mjs`

A wrong-but-well-formed `bodySha256` passes every check runnable on a dev machine and then **bricks
every boot**. There is no generator in the repo; this adds one.

- [ ] **Step 1: Write it**

```js
#!/usr/bin/env node
// Print the bodySha256 the SECURITY DEFINER certificate expects for every function in a migration.
//
// The certificate computes, in SQL:
//   encode(sha256(convert_to(replace(prosrc, chr(13), ''), 'UTF8')), 'hex')
// `prosrc` is the body BETWEEN the `$$` delimiters — nothing else. The CR strip is load-bearing:
// packages/db/src/migrations/ carries no `eol=lf` pin, so a Windows checkout stores CRLF and Linux
// CI stores LF, and a raw hash would pin one platform and fail boot on the other.
//
// Usage: node scripts/definer-body-sha256.mjs packages/db/src/migrations/0268_*.sql
import { readFileSync } from "node:fs";
import { createHash } from "node:crypto";

const file = process.argv[2];
if (!file) {
  console.error("usage: node scripts/definer-body-sha256.mjs <migration.sql>");
  process.exit(2);
}
const sql = readFileSync(file, "utf8");
const names = [...sql.matchAll(/CREATE OR REPLACE FUNCTION\s+(?:public\.)?(\w+)/g)].map((m) => m[1]);
const bodies = [...sql.matchAll(/AS \$\$([\s\S]*?)\$\$;/g)].map((m) => m[1]);
if (names.length !== bodies.length) {
  console.error(`function/body count mismatch: ${names.length} vs ${bodies.length}`);
  process.exit(1);
}
for (const [i, name] of names.entries()) {
  const hash = createHash("sha256").update(bodies[i].replace(/\r/g, ""), "utf8").digest("hex");
  console.log(`${name}\n  ${hash}`);
}
```

## Task 3: Migration 0268 — the classification read

**Files:** Create `packages/db/src/migrations/0268_legacy_reconciliation_lease_read.sql`

- [ ] **Step 1: Determine the minimal projection**

The union of what `resolveResourceType`, `classifyLease`, `computeResourceLabelsHash` and
`buildLeaseRecord` actually read is **eleven** columns: `id`, `company_id`, `environment_id`,
`status`, `lease_policy`, `provider`, `provider_lease_id`, `agent_id`,
`commander_conversation_id`, `execution_workspace_id`, `cleanup_status`.

★ `issue_id` and `heartbeat_run_id` are declared on `LegacyLeaseInput` and read by **nothing** — omit
them. ★★ `metadata` is **secret-bearing at rest** (`sanitizeProviderMetadata` strips `apiKey` /
`resolvedApiKey` at read time, in memory, not on disk) and `failure_reason` is operator text; **both
must be named as excluded in the migration comment, not merely left out** — an omission reads as an
oversight to the next author, an exclusion reads as a decision.

- [ ] **Step 2: Write the migration**

Follow `0267`'s shape exactly: a leading C14 block comment, then **a per-statement C14 comment on
every statement** (Decision #122 condition 3), `SET search_path = ''` with every relation
schema-qualified, `REVOKE ALL … FROM PUBLIC`, `REVOKE ALL … FROM "aoa_app"`, `GRANT EXECUTE … TO
"aoa_operator"`.

The function is **organization-bound**, mirroring `canary_preflight_evidence_leases`:

```sql
CREATE OR REPLACE FUNCTION public.legacy_reconciliation_leases(
  p_organization_id uuid, p_company_id uuid)
RETURNS TABLE (
  id uuid, company_id uuid, environment_id uuid, status text, lease_policy text,
  provider text, provider_lease_id text, agent_id uuid, commander_conversation_id uuid,
  execution_workspace_id uuid, cleanup_status text
)
LANGUAGE sql
STABLE
SECURITY DEFINER
SET search_path = ''
AS $$
  SELECT l.id, l.company_id, l.environment_id, l.status, l.lease_policy,
         l.provider, l.provider_lease_id, l.agent_id, l.commander_conversation_id,
         l.execution_workspace_id, l.cleanup_status
  FROM public.environment_leases l
  WHERE l.company_id = p_company_id
    AND EXISTS (SELECT 1 FROM public.companies c
                WHERE c.id = p_company_id AND c.organization_id = p_organization_id);
$$;
```

★ **NO new parameter carries a DEFAULT, now or ever.** The certificate is blind to
`proargdefaults`: a `CREATE OR REPLACE` changing only a default leaves `identity_arguments`,
`proconfig`, `proacl` and `sha256(prosrc)` byte-identical while changing what the function returns.
That is a fail-open with a green certificate (design §10.2, measured).

★ This is a **new name**, so there is no old overload and no `DROP` is required. Do not rename or
re-arity `canary_preflight_evidence_leases` in this unit.

```bash
cd /c/e3 && pnpm db:generate --custom --name legacy_reconciliation_lease_read
```

Then verify the snapshot is byte-identical to `0267_snapshot.json` apart from `id`/`prevId`, and that
