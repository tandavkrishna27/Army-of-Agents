## Task 2: The resolution command

**Files:** Create `server/src/cli/resolve-unattributable-record.ts`; modify `package.json`

Follow `reconcile-legacy-resources.ts` exactly — `createDb(process.env.DATABASE_URL)`, and the
`current_user = 'aoa_operator'` assertion **before the first read**. Without it an owner URL gives a
green run that proves nothing about the grant model.

- [ ] **Step 1: Arguments** — `--company <uuid> --resource-key <key> --reason "<justification>"`.
  One record at a time. **No bulk mode**: a bulk clear is how a register of unresolved problems
  becomes a register of nothing.

- [ ] **Step 2 ★★★: The transition is `unattributable → terminal_cleanup` ONLY**

Guard it in the `WHERE` clause, not in TypeScript:

```sql
UPDATE legacy_resource_reconciliation
   SET disposition = 'terminal_cleanup', reason = $3, cleanup_outcome = 'operator_resolved'
 WHERE company_id = $1 AND resource_key = $2 AND disposition = 'unattributable'
```

★ **It may never mint `mapped`.** `mapped` is the disposition that says "a live resource is accounted
for and left for drain" — an operator asserting that about a resource *nobody could classify* is
exactly the forgeable claim. The `WHERE disposition = 'unattributable'` predicate also makes the
command idempotent and makes a second run a no-op rather than a silent overwrite.

- [ ] **Step 3:** Refuse an empty or whitespace-only `--reason`, and exit non-zero. The justification
  is the audit trail; a blank one is worse than none because it looks like a record.

- [ ] **Step 4:** Report what it changed — 0 rows means "no such unattributable record", which is a
  different outcome from success and must exit differently.

- [ ] **Step 5: Commit.**
