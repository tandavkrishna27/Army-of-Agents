# Current-main Execution Crosswalk

**Observed current-main baseline:** `003492988269a91eadfadb352bff7f413fa61adb` (includes PR #320 Cloud Execution Isolation at `861134f6e5d8d95de2484a44fadc5818062b2049` and the subsequent explicit migration-0188 deployment marker flow)

**Execution freeze:** This program executes against a **frozen main revision**. Before E0 begins, main is frozen and its exact SHA is recorded here (superseding the observed baseline above if main has advanced). Every gate, crosswalk-row closure, and ticket verifies against that pinned SHA fetched from `origin/main` — never a local checkout, which may lag origin and lack the characterized code. Advancing the frozen SHA is a Migration-Custodian decision recorded with its rationale, and it re-opens any crosswalk row whose characterized code changed.

**Purpose:** Freeze the execution paths that exist before the distributed worker re-platform and assign every path an explicit bridge, cutover, disablement, drain, rollback, and evidence owner. This is an observed migration inventory, not a new architecture authority. Locked decisions and [`program-design.md`](program-design.md) remain controlling.

## Reading rule

No ticket may replace a row by inference. Its owning migration ticket must characterize the observed path on the frozen baseline, implement the named disposition, prove that shadow mode causes no effects, identify active-work handling, and retain rollback and hard-negative evidence. Until that ticket passes, the current owner remains authoritative. There is never a permanent dual writer or a silent host fallback in `cloud_auth`.

Migrating the CM-002/CM-003/CM-005 primitives migrates all of the above call-sites automatically.

## Closure rule

The Migration Custodian maintains this crosswalk. A row closes only when its named ticket result and immutable QA/handoff evidence identify the exact revision, record the before/after owner, show shadow/cutover/drain/rollback behavior, and demonstrate the required hard negatives. E0 cannot pass until CP-001 through CP-005 are closed. MIG-002 may complete only after CM-001 through CM-015 are closed or an owning ticket records an approved fail-closed disablement for a genuinely unsupported source; an exposure flag is not closure. REL-005 may begin only after all mandatory coding, browser, and service rows are closed and their D2–D4 gates pass.
